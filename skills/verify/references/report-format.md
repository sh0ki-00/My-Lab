# 完了報告の型

> **3 行でわかる要約**
> 1. 完了報告は、受け入れ条件 1 件ごとに「確認コマンドと結果」を対にして書く文書で、`.company/rules/evidence-and-safety.md` の証拠の決まりを形にしたものです。
> 2. 必須は 5 つです。3 行の要約・受け入れ条件の表・直したことの表・未確認の表・検証の記録への参照です。
> 3. 書いたら `scripts/report-check.sh` を通し、別コンテキストの読み手テスト（My-Lab では `editor`）を受けてから社長に出します。

## 1. 必須の節

社長は報告を 1 分で判断します。最初の 10 行で「何が終わり、何が終わっていないか」が分かるように、要約と表を先に置きます。

| 節 | 中身 | 検査（report-check.sh） |
|---|---|---|
| 表題 | `# 完了報告: <件名>` | 表題が「完了報告:」で始まる |
| 3 行の要約 | 何の作業か、結果（全体 PASS か、未確認の数）、依頼者にしてほしいこと | 引用ブロックに 3 行 |
| 受け入れ条件 | 列は「#」「条件」「確認コマンド」「結果」。結果は実行して出た値の抜粋 | 表があり、全行の結果が空でなく、`<…>` の穴が無い |
| 直したこと | 列は「場所」「何を」「なぜ」。検証の FAIL を直した記録 | 表がある（無ければ「無し」と 1 行） |
| 未確認 | 列は「条件」「理由」「確かめ方」。確かめられなかった条件を黙って「充足」にしない | 節があり、各行に理由がある |
| 検証の記録 | `docs/verify/<日付>.md`（他のプロジェクトでは `tmp/.verify/last-fast.txt` か `tmp/.verify/last-full.txt`）への参照 | 参照がある |

## 2. 書いてはいけない言い方

実行していないことを、実行したように書く言い方を禁止します。推測の語は、検査が落とします。

| 言い方 | 理由 | 代わり |
|---|---|---|
| 動くはず、通るはず | 実行していない | 実行し、結果を書く。できないなら未確認に |
| と思われる、おそらく | 推測 | 確かめ方を書き、未確認に |
| 確認済み（コマンド無し） | 何を見たか分からない | 確認コマンドと結果の抜粋 |
| 問題なし | 何を見たか分からない | 見た項目と、出た値 |

## 3. 例

`examples/completion-report-stage0.md` は、段階 0 の完了報告の完成例です。受け入れ条件 7 件の全行に確認コマンドと結果があり、未確認は理由つきで 2 件あります。
