# 会議の型と会議録

> **3 行でわかる要約**
> 1. 秘書が役割を動かす会議の 3 つの型と、司会の手順、会議録の欄をまとめた文書である。
> 2. 会議は黙読から始め、各役割は要点だけを返し、秘書は最後に話す。対立は事実で裁き、裁けないものは社長に聞く。
> 3. My-Lab ではサブエージェント（別の文脈で動く補助の AI）を並列に出し、他のプロジェクトでは役割を順に演じる。会議録の形は同じにする。

## 1. 3 つの型

会議は 3 つの型だけにする。型を増やさないのは、どの依頼でも同じ会議録が残るようにするためである。

| 型 | いつ | 進め方 | 終わりの印 |
|---|---|---|---|
| 黙読会議 | 受付票ができた直後 | 全員が受付票を読んでから、自分への問いに答える。秘書は最後に話す | 役割の返答の表が埋まる |
| 対立の裁定 | 役割の意見が割れたとき | 決め手になる事実を探し、事実で決まるものは秘書が裁く。決まらないものは未解決へ | 対立点と裁定の表が埋まる |
| 承認伺いの前審査 | 社長に出す直前 | 結論 3 文と伺い 1 点が先頭か、空行を除いて 60 行以内か、禁止の語が無いかを見る | approval-request-check が PASS |

## 2. 司会の手順

司会は秘書が務める。手順は 7 つで、黙読と「最後に話す」を外さない。会議 1 回の目安は 15 分で、試運転では 4 役割の返答に 9〜15 分かかった。長い文書は黙読に向くが、1 時間の会議なら 6 ページ、30 分なら 3 ページが上限である（出典 1）。

| # | 手順 | なぜ |
|---|---|---|
| 1 | 受付票を黙読の文書にし、会議録の「黙読した文書」にパスと行数を書く | 読んでいない役割を会議に入れない |
| 2 | 役割ごとの問いを 1 つずつ渡す。題材・入力ファイル・出力先を全部書く | 役割は会話の履歴を持たない（出典 4） |
| 3 | 返答は雛形（`skills/secretary/templates/reply-from-role.md`）の 3 節で受け取り、要約は 10 行以内。15 分を目安に待ち、超えたら要約だけを先に求める | 秘書の文脈を汚さない。会議録を薄くしない（出典 3） |
| 4 | 反対意見を集めに行く。賛成だけの会議は情報が足りないと疑う | 決めたあとの蒸し返しを防ぐ（出典 2） |
| 5 | 対立は事実で裁く。反対した役割が従うと表明したかを記録する | 決める人は 1 人で、決まったら従う |
| 6 | 作業を始めようとした役割を止め、「承認が要る判断」に移す | 承認前は読むだけ |
| 7 | 受け渡しの穴（相手の返答が無いと埋まらない点）が 2 つ以上なら、相手の返答を渡して 2 巡目を回す | 並列に出した役割は、相手の返答を見られない |

## 3. My-Lab と他のプロジェクトでの回し方

回し方は、道具ではなく置き場で変える。サブエージェントの定義は My-Lab の .claude/agents/ の下にだけある。Claude Code も Cursor もそれを読む。他のプロジェクトには定義が写らないので、秘書がペルソナ（役割の定義書）を読んで役割を順に演じる。会議録の形はどちらも同じにする。

| 項目 | My-Lab | 他のプロジェクト（`tmp/` の写し） |
|---|---|---|
| 役割の動かし方 | `.claude/agents/<役割>.md` を並列に呼ぶ | `tmp/.company/<役割>/CLAUDE.md` を読み、1 役割ずつ演じる |
| 渡すもの | 依頼文に題材・入力ファイル・出力先・返す形を全部書く | 同じ内容を自分への指示として書く |
| 受け取るもの | 要約 10 行以内、未解決の対立、承認が要る判断 | 同じ 3 つを会議録に写す |
| 読み手テスト | 秘書が `editor` サブエージェントに文書だけ渡す（役割からは呼べない） | Claude Code は組み込みの general-purpose サブエージェントに文書だけ渡す。Cursor は秘書が読み手の役に切り替えて演じ分ける |

他のプロジェクトの読み手テストには general-purpose を使う。Claude Code に最初からある補助の AI で、定義を写さなくても呼べるからである。依頼文には文書の本文と 3 問だけを書き、書いた経緯は渡さない。

## 4. 会議録の欄と検査

会議録は雛形（`skills/secretary/templates/minutes.md`）の 5 つの節で書き、`skills/secretary/scripts/minutes-check.sh` が検査する。生のログ（50 行を超えるコードブロック）が貼ってあると落ちる。

| 節 | 書くこと | 落ちるもの |
|---|---|---|
| 会議の概要 | 受付番号、日時、型、黙読した文書のパス、参加した役割 | パスが無い、一覧に無い役割 |
| 役割の返答 | 役割・問い・要点（300 字以内）・根拠 | 空のセル、300 字超 |
| 対立点と裁定 | 対立点・誰と誰・決め手の事実・裁定・依頼者に伺うか | 空のセル（0 件は注意） |
| 未解決 | 事実が無くて決められない問いと仮置き | 節が無い |
| 承認が要る判断 | 判断・種類（戻せる／戻せない）・伺い方 | 種類が 2 語以外 |
