# 報告の門

> **3 行でわかる要約**
> 1. 社長に文書を出す直前に秘書が見る門の 7 つの自問と、その根拠、機械の検査、読み手テストをまとめた文書である。
> 2. 1 つでも「はい」なら出さず、作った役割に戻す。門の項目は根拠つきで持ち、追加は社長の承認で、年に 1〜2 回棚卸しする。
> 3. 機械の検査は `skills/secretary/scripts/gate-check.sh` で、言い訳の語・要件の交渉・判定の転記・推測・検証の記録の欠けを落とす。

## 1. 7 つの自問と根拠

門は組織図（`.company/ORG.md`）の 7 つの自問で、納品の決まり（`.company/DELIVERY.md`）の各条と対になる。各行に根拠を添えるのは、根拠の無い項目は守られなくなるからである（出典 1）。根拠の欄は、今は想定する失敗で埋めてある。実例が出たら、その記録に置き換える。

| # | 自問 | 根拠（想定する失敗。実例が出たら置き換える） | 機械で見る検査 |
|---|---|---|---|
| 1 | 要件を満たした資産を伴わずに、報告だけを出そうとしていないか | 分析だけの報告に、社長が「何ができたのか」と聞き返す | gate-check の出す前の表 |
| 2 | 「できませんでした」を資産の代わりにしていないか | 言い訳の段落が、資産の欄を埋める | gate-check の言い訳 |
| 3 | 要件の緩和や二者択一を、社長に迫っていないか | 「A と B は両立しません」と社長に選ばせる | gate-check の要件の交渉 |
| 4 | 社内の審査の否定的な判定を、そのまま転記していないか | 「QA の判定: 不合格」をそのまま貼る | gate-check の判定の転記 |
| 5 | 第 4 条の輪を回し切らずに出していないか | 1 回試して諦め、改善案を 3 つ出していない | 完了報告の「直したこと」の節（report-check） |
| 6 | 実行していない検証や、測っていない数値を書いていないか | 「通るはず」で出して、本番で落ちる | gate-check の推測、report-check |
| 7 | 検証の記録が付いているか | 記録なしで「完了」と書く | gate-check の検証の記録 |

## 2. 門の増減

門の項目は増やすほど守られなくなる。項目の追加は社長の承認で行い、年に 1〜2 回は全項目を見直して根拠の無い項目を外す（出典 1）。gate-check の WARN は棚卸しの入力にする。

| 操作 | 誰が | いつ |
|---|---|---|
| 項目を足す | 社長が承認し、秘書が組織図とこの文書に書く | 同じ失敗が 2 回出たとき |
| 項目を外す | 秘書が提案し、社長が承認する | 年 1〜2 回の棚卸し |
| 根拠を置き換える | 秘書 | 実例が出たとき |

## 3. gate-check が落とすもの

`skills/secretary/scripts/gate-check.sh` は、社長向けの文書（承認伺いと完了報告）を機械で見る。表題の「承認伺い:」「完了報告:」で種類を判定し、どちらでもなければ言い訳・交渉・転記の検査だけを行う。

| 決まり | 落とす語や形 | 例外 |
|---|---|---|
| 言い訳 | できませんでした、限界、両立しません、前より良く、概ね、暫定版、未達、未充足 | 同じ行に承認記録 A-番号か「社長の判断」がある |
| 要件の交渉 | どちらを外、要件を緩め、どちらか一方を | なし |
| 判定の転記 | 「〜の判定:」「〜より:」で始まる行 | なし |
| 推測（完了報告） | 動くはず、通るはず、と思われ、おそらく | なし |
| 検証の記録（完了報告） | My-Lab では docs/verify/ への参照が無い。他のプロジェクトでは tmp/.verify/last-fast.txt か last-full.txt への参照が無い | なし |
| 出す前の表（完了報告） | 判定の列に「充足」以外 | A-番号が添えてある行 |
| 順番と長さ（承認伺い） | 最初の節が「結論と伺い」でない。空行を除いて 60 行超 | なし |

## 4. 読み手テスト

機械の門のあとに、別コンテキストの読み手テストを行う。My-Lab では `editor` に文書だけを渡す。これは添削専用のサブエージェント（別の文脈で動く補助の AI）である。他のプロジェクトでは `editor` が写らない。Claude Code は組み込みの general-purpose サブエージェントに文書だけを渡し、Cursor は秘書が読み手の役に切り替えて演じ分ける。どの置き場でも、書いた本人には答えさせない。

| 文書 | 問い | 正答の条件 |
|---|---|---|
| 承認伺い | 推奨は何か。伺いは何か。承認で何が始まるか | 3 問とも、文書の文だけで答えられる |
| 完了報告 | 何ができたか。何が未確認か。証拠はどこか | 3 問とも、文書の文だけで答えられる |
