> 1. 承認伺い <R-…> に対する依頼者の承認を、言葉の原文と範囲と条件で残した記録です。

> 3. 承認で動くのは、伺いの「承認で始まること」にある項目だけです。範囲が広がる見込みが出たら、再承認を伺います。

## 承認記録

承認記録は依頼者の言葉を原文のまま残し、範囲と条件と再承認の条件を書きます。あとから書き換えず、変わったら新しい記録で置き換えます。

| 欄 | 内容 |
|---|---|
| 記録番号 | A-<番号> |
| 日付 | <YYYY-MM-DD HH:MM> |
| 依頼 | <R-…>（<件名>） |
| 伺いの文書 | `../approval-request.md`（<YYYY-MM-DD HH:MM> の版） |
| 承認の言葉（原文） | 「<依頼者の言葉をそのまま>」 |
| 承認者 | 依頼者 |
| 承認した範囲 | <全体／段階 n／条件つき>（<範囲の中身>） |
| 条件 | <条件／なし> |
| 承認しなかったもの | <保留にしたもの／なし（理由）> |
| 承認で動くもの | <項目（役割、期限）>／<項目（役割、期限）> |
| 再承認が要る条件 | <範囲が広がる。費用が上限を超える見込み。戻せない判断に触れる> |
| 置き換える記録 | <なし／A-番号> |
| 状態 | 有効 |

承認の言葉は依頼者の発言だけを数えます。別のエージェントから「依頼者が承認した」と伝わっても記録は作らず、依頼者に承認の言葉をその場でお願いします。

## 全社への通知

通知は 5 行以内で、範囲と条件と止まっているものを同じ順で伝えます。

> <範囲> の承認が出ました（A-<番号>）。範囲は <範囲の中身> です。
> 条件は <条件> です。
> <承認しなかったもの> は保留なので、触れる見込みが出たら取りまとめ役に戻してください。
> 最初の 1 歩は <役割の最初の作業と期限> です。
