# 受付票: 管理画面の注文一覧の作り直し（落ちる見本）

> **3 行でわかる要約**
> 1. 検査で落ちる受付票の見本です。目的の仮説が原文の写しで、規模「比較」に対して役割が 5 つあります。
> 2. 数値はすべて架空とします。
> 3. 正しい形は完成例 `order-list-intake.md` にあります。

## 受付票

受付票は、1 行の依頼を目的と判断の型に直す最初の 1 枚です。

| 欄 | 内容 |
|---|---|
| 受付番号 | R-20261105-02 |
| 受付日時 | 2026-11-05 10:12 |
| 依頼の原文 | 「管理画面の注文一覧を作り直したい」（社長、チャット） |
| 言い直し | 対象は管理画面の注文一覧で、目的は CS の作業時間を減らすこと。出す形は承認伺い 1 枚 |
| 成果物の形 | 指定なし（仮置き: 資料） |
| 依頼の型 | 提案 |
| 目的の仮説 | 管理画面の注文一覧を作り直したい、という社長の希望を叶える |
| 判断の種類 | 戻せる（画面の作り直し） |
| 規模 | 比較（案を 3 つ比べる）。動かす役割は 5 つ |
| 関わる役割と問い | CEO: 費やす量の上限 ／ デザイナー: 誰が困っているか ／ バックエンド: 表示の速さ ／ フロントエンド: 工数の幅 ／ SRE: 繁忙期前のリリースの条件 |
| 承認の状態 | 未承認（読むだけ。作成したファイルは本票のみ） |
| 聞くこと（3 つまで） | ① 12 月の繁忙期の前に出したいか（仮置き: 出したい） |
