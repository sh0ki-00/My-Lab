# カタカナ語の言い換えと、残してよい技術用語

> **3 行でわかる要約**
> 1. 業務の文書に出るカタカナ語 16 語の言い換え表と、言い換えずに残してよい技術用語の一覧です。
> 2. 根拠は国立国語研究所『「外来語」言い換え提案』（176 語）と、文化庁『公用文作成の考え方』の外来語の扱いです。
> 3. 言い換え表の語は `scripts/katakana.txt`、残す語は `scripts/allow-katakana.txt` にあり、`fluency-check.sh` が読みます。

## 1. 言い換える語

言い換えるのは、業務の文書に出やすいカタカナ語 16 語です。読み手がエンジニアでも、日本語のほうが短く伝わります。文の意味が変わるときは、左の語を残して括弧で説明します。

| カタカナ語 | 言い換え | カタカナ語 | 言い換え |
|---|---|---|---|
| アジェンダ | 議題 | マネジメント | 管理、経営 |
| インタラクティブ | 双方向 | リテラシー | 読み書きの力 |
| ガバナンス | 統治、管理の仕組み | ロードマップ | 行程表 |
| コンセンサス | 合意 | トレンド | 傾向 |
| コンプライアンス | 法令遵守 | ニーズ | 要望 |
| スキーム | 計画、仕組み | バリアフリー | 障壁なし |
| スタンス | 立場 | オンデマンド | 求めに応じて |
| ソリューション | 解決策 | プライオリティ | 優先順位 |

もとの表は 40 語で、読み手を依頼者や新人と置いて作っていました。実際の読み手はエンジニアなので、エンジニアが日常に使う 24 語は言い換えない語に移しました（2026-11-27、2 節）。

## 2. 残してよい技術用語

日本語で言い換えると遠回りになる語です。初出で括弧の説明を付けて残します。

| 残す語 | 初出の説明の例 |
|---|---|
| キャッシュ | 一度取った結果を取っておく仕組み |
| サーバー、ブラウザ、データベース、ネットワーク、クラウド | 一般に通じるので説明は省いてよい |
| リポジトリ、コミット、ブランチ、マージ、プルリクエスト、リベース、プッシュ | git の語。言い換えない。説明が要る読み手にだけ、初出で括弧の説明を添える |
| デプロイ、リリース、ロールバック | 本番に出す、前の版に戻す |
| ログ、エラー、テスト、バックアップ、バージョン | 一般に通じる |
| トークン、セッション、クッキー | 認証の語。初出で説明する |
| オフセット、カーソル、インデックス | 技術用語として残す。インデックスは言い換えない |
| アクセス、インフラ、インプット、アウトプット、オペレーション、キャパシティ、ステータス、タスク、ツール、デフォルト | エンジニアが日常に使う語。言い換えない（2026-11-27 に 1 節から移した） |
| パフォーマンス、フィードバック、プロセス、メンテナンス、モニタリング、ユーザー、リソース、レスポンス | 同上 |
| スケジュール、シミュレーション、コンテンツ、リスク、ガイドライン、ベンダー | 同上 |
