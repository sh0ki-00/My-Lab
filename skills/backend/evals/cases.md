# backend の試験ケース

`run.sh` が回す試験ケースは 6 件です。どれも機械で合否が決まり、1 件でも落ちたら提出しません。

| # | ケース | 与えるもの | 合格の条件 |
|---|---|---|---|
| 1 | 完成例と雛形 | 計画の完成例と雛形、契約の完成例と雛形 | 完成例は通り、計画の雛形は穴で落ちる。契約の 2 つは 1 版の決まりを通る |
| 2 | 計画の欠け | `fixtures/bad-plan.md` | 契約・認可・冪等・エラー・移行・問い合わせ・性能予算・観測・流出経路・テスト・段階・必須の節の 12 で落ちる |
| 3 | 契約の欠けと壊す変更 | `fixtures/bad-contract.json`、壊した 2 版目 | 4 つの決まりと 6 種類の壊す変更で落ちる。同じ版どうしは通る |
| 4 | 問い合わせの数と p99 | 見本の API と、わざと N+1 にした写し | 見本は 24 件と 400 件で SQL の数が同じで、p99 が予算内。写しは N+1 で落ちる |
| 5 | 見本の API の振る舞い | `samples/api/test_orders_api.py` | 80 本の試験が全部通る（PostgreSQL の容器が無ければ、その 6 本は飛ばす。契約の形、認可、冪等、旧 API と新 API の 4 つの決まり、足し算の移行、since、HTTP の入口、エラー、ログ、DB の権限の一覧、注入） |
| 6 | 既存のデータを読む道具 | `fixtures/data/shop.sql` のサンプルの DB、辞書と調査の文書の正例、記録の負例 2 つ | 写し・集計・クエリ・書き込む処理が通り、正例は検査を通る。結論の数を変える、辞書に無い値で絞る、UPDATE の文を混ぜる、読み取り専用でない開き方などの負例は決まりの名前で落ちる。査読のあとに、別名の個人情報、\r の注釈、結論の数の 5 つの書き方、データの節の根拠、基準の数字などの負例を足した。テンプレートは穴で落ちる。辞書の完成例 `examples/data-dictionary-messy-shop.md` は `--root samples/messy-shop` で通る。git の無いプロジェクトの辞書は、commit の欄が「git なし」と作った時刻と根拠のハッシュ値なら通り、ハッシュ値が無いか、git の作業ツリーの中か、根拠のファイルが変わると [鮮度] で落ちる |
