# backend の試験ケース

`run.sh` が回す試験ケースは 5 件です。どれも機械で合否が決まり、1 件でも落ちたら提出しません。

| # | ケース | 与えるもの | 合格の条件 |
|---|---|---|---|
| 1 | 完成例と雛形 | 計画の完成例と雛形、契約の完成例と雛形 | 完成例は通り、計画の雛形は穴で落ちる。契約の 2 つは 1 版の決まりを通る |
| 2 | 計画の欠け | `fixtures/bad-plan.md` | 契約・認可・冪等・エラー・移行・問い合わせ・性能予算・観測・流出経路・テスト・段階・必須の節の 12 で落ちる |
| 3 | 契約の欠けと壊す変更 | `fixtures/bad-contract.json`、壊した 2 版目 | 4 つの決まりと 6 種類の壊す変更で落ちる。同じ版どうしは通る |
| 4 | 問い合わせの数と p99 | 見本の API と、わざと N+1 にした写し | 見本は 24 件と 400 件で SQL の数が同じで、p99 が予算内。写しは N+1 で落ちる |
| 5 | 見本の API の振る舞い | `samples/api/test_orders_api.py` | 80 本の試験が全部通る（PostgreSQL の容器が無ければ、その 6 本は飛ばす。契約の形、認可、冪等、旧 API と新 API の 4 つの決まり、足し算の移行、since、HTTP の入口、エラー、ログ、DB の権限の一覧、注入） |
