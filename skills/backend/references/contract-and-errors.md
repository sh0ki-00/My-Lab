# 契約とエラーと冪等の決め方

> **3 行でわかる要約**
> 1. API の契約・エラー・冪等キー・一括の書き込みを、どう決めるかの参考資料です。
> 2. 契約を先に OpenAPI 3.1 の JSON で書き、壊す変更は版を分けます。エラーは 4 点、書き込みは冪等キーを必須にします。
> 3. 計画を書くときに、この表で決めを確かめ、`scripts/contract-check.sh` を通してください。

## 契約を先に書く

契約は、画面と API が同じ形を見るための約束です。コードより先に OpenAPI 3.1（API の形を書く国際的な書式）の JSON で書きます。YAML を読む道具が無い作業場でも、JSON なら標準の道具で検査できます。

| 決めること | 決め方 |
|---|---|
| 操作 | 画面の操作と 1 対 1。画面の 1 回の表示に要る物は、1 回の要求で返す |
| 応答の欄 | 画面の要素表から逆に決める。件数と利用者とサーバーの時刻は一覧と同じ応答に入れる |
| 時刻 | UTC の RFC 3339。固定幅の文字列で保存し、文字列の大小と時刻の前後を一致させる |
| 金額 | 円の整数。小数で持たない |
| 版 | パスの頭に `/v1`。壊す変更は `/v2` を足し、旧版の呼び出しが 0 回になってから消す |

## 壊す変更と壊さない変更

壊す変更とは、今の呼び手がそのままでは動かなくなる変更です。検査は 6 種類を落とし、足すだけの変更は通します。

| 変更 | 壊すか | 理由 |
|---|---|---|
| 操作の削除 | 壊す | 呼び手の要求が 404 になる |
| 応答の欄の削除 | 壊す | 呼び手が読む欄が消える |
| 必須の入力の追加 | 壊す | 今の要求が 400 になる |
| 型の変更 | 壊す | 呼び手の型の検証が落ちる |
| 列挙値の削除 | 壊す | 今の値を送ると 400 になり、受け手の分岐が外れる |
| 応答の状態番号の削除 | 壊す | 呼び手のエラーの分岐が外れる |
| 任意の引数、応答の欄、状態番号の追加 | 壊さない | 呼び手は知らない欄を読み飛ばす |

## エラーの 4 点

エラーの本文は、分類・原因・対処・追跡番号の 4 点とコードを必ず持ちます。画面は文をコードの鍵から引き、追跡番号を「お問い合わせ番号」として出します。

| 欄 | 中身 | 例 |
|---|---|---|
| code | 画面仕様のエラー表と同じ名前 | ORDER_NOT_FOUND |
| category | 分類。auth、permission、validation、not_found、conflict、upstream、internal | not_found |
| cause | 原因。何が起きたか | この注文は見つかりませんでした |
| action | 対処。どうすればよいか | 注文番号を確かめて、一覧から開き直してください |
| traceId | 追跡番号。ログと見出しと同じ | 32 桁の 16 進数 |

## 一覧の送り

一覧は起点の送りにします。OFFSET（先頭から数えて飛ばす送り方）は、取得の間に行が動くと行を飛ばします。起点は中身を読ませない文字列にし、API の鍵で署名します。署名が無いと、画面や攻撃者が組み立てた起点で別の群へ飛べます。`limit` に上限を付けます。

| 決め | 中身 |
|---|---|
| 起点 | 並び順の列を全部（例: 群・受注日時・番号）。最後の行の値から次を取る |
| 上限 | `limit` の maximum を契約に書く。見本は 100 |
| 次の起点 | 応答の `nextCursor`。最後なら null |
| 起点が古くなる時 | 群が日付で決まるなら、起点を日付に結びつけ、日付が変わったら 400 にする。送りの途中で群が前に戻った行は、最初の頁の時刻からの `since` で届ける。起点の送りだけで「行を飛ばさない」とは書かない |
| 変化の取得 | `since` にサーバーの時刻を渡し、変わった行だけを返す。行が変わったら必ず進む印（DB のトリガーが進める changed_at）で数える。済や取消の時刻で数えると、取り消しの戻しなどが抜ける。サーバーの時刻は changed_at と同じ DB の時計で取る。重ね幅は、その表を書く全部の DB の利用者の取引の上限より長くし、上限は DB の側で掛ける。一覧のサーバーの時刻は、行を読んだ文と同じ文で取る。`since` には窓（例: 15 分）を付け、古い時刻は 400 にする。窓が無いと、鍵 1 本で店の全履歴をたどれる。返すのは、どの書き手の変更でも変わった行で、済の行だけではない |
| 引数の読み方 | 空の値、同じ引数の重ね、= の無い引数、契約に無い引数は、黙って捨てずに 400。標準の読み方（parse_qs）は空の値を捨てる |

## 冪等キーと一括の書き込み

書き込みは冪等キーを必須にします。キーは店と利用者ごとに分けて保持し、期間を過ぎたら消します。同じキーで違う内容が来たら 422 を返し、何も書きません。冪等キーの行は、注文の行を読む前に先に入れます。同じキーの 2 本目は、その INSERT で 1 本目のコミットを待ち、主キーの重複で失敗します。行を先に読むと、行の鍵で待つ DB では古い行を読んだまま更新が 0 行になり、500 を返します。

一括の書き込みは、条件つきの UPDATE の 1 文で書ける行だけを書き、書けた行を RETURNING で受けます。書けなかった行は、そのあとで読んで行ごとの結果に分けます。先に読んでから書くと、行の鍵で待つ DB では 2 人目の更新が 0 行になり、500 になります。先に済の行や、状態が合わない行は書きません。途中で失敗したら全部を戻し、どこまで書けたか分からない状態を作りません。

| 場面 | 応答 |
|---|---|
| 書けた行が 1 件以上 | 200。行ごとの結果と件数の要約 |
| 全件が先に済 | 409。行ごとの結果つき |
| 書けた行が 0 件 | 409。行ごとの結果つき |
| 同じキーで同じ内容 | 最初の応答。見出し `Idempotent-Replayed: true` |
| 同じキーで違う内容 | 422 |
