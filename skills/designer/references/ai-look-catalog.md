# AI の既定の見た目の目録

> **3 行でわかる要約**
> 1. 生成 UI が「平均」に落ちるときの見た目を、機械で見つけられる形で並べた目録である。`skills/designer/scripts/ai-look-check.sh` の検出項目と帯の意味も書く。
> 2. 既定は悪ではない。依頼が名指しした既定には従い、計画書の「既定との差」に理由を書けば件数から外す。差を言えない選択だけが既定である。
> 3. 帯は 4 段（clean・mild・sloppy・terminal）で、件数で決まる。監修を通るのは clean だけである。

## 1. 3 つの見た目と 1 つの型

生成 UI の既定は 4 系統に集まる。どれも単体では間違いではないが、依頼の主題と無関係に現れるので、計画書で名指しして外す。

| 系統 | 見た目 | なぜ既定に見えるか |
|---|---|---|
| 雑誌風 | クリーム地（#F4F1EA のような）に高コントラストのセリフ体、テラコッタの強調 | 読み物の型を管理画面にも当てはめる。主題と無関係に出る |
| 監視室 | 黒地（#020617 のような）に蛍光の緑か朱の 1 色、等幅の見出し | 「運用」の語に反応して出る。明るい事務所では目が疲れる |
| 新聞風 | 罫線だけで区切る白地、太い見出し、余白の多い段組 | 構造を罫線で代用する。密度が要る画面で情報が薄くなる |
| 着地ページの型 | 紫のグラデーション（#6366F1 由来）、Inter、均一な角丸 16px と影、3 枚のカード、01/02/03 の番号、絵文字のアイコン、Get Started | 部品集の既定値をそのまま使う。どの依頼でも同じ形になる |

## 2. 検出項目

`ai-look-check.sh` は実装のコード（css・html・js・tsx・vue・svelte）を走査し、次の項目を数える。計画書を `--plan` で渡すと、「既定との差」の表に 10 字以上の理由がある項目を件数から外す。

| 項目 | 機械で見る印 | なぜ既定に見えるか | 意図して使うなら書く理由の例 |
|---|---|---|---|
| 既定色 | #6366F1、#8B5CF6、#7C3AED、#A855F7、#667EEA、#764BA2 などの紫 | 部品集の indigo-500 の系譜。依頼の主題と無関係 | 「製品の既存のブランド色が #6366F1」 |
| グラデーション | bg-gradient-to-、from-purple、既定色の linear-gradient | 着地ページの型の中心 | 「依頼が紫のグラデーションを名指しした。置き場は見出しの帯 1 か所」 |
| ぼかし | backdrop-filter: blur が 3 か所以上 | ガラス風の多用。読みにくく重い | 「通知 1 か所だけ。背景の表を透かして見せるため」 |
| 絵文字 | マークアップの中の絵文字 | アイコンの代わり。読み上げと等幅が崩れる | 「社内の非公式の掲示板で、絵文字が文化」 |
| 動き | transition: all、animate-pulse、animate-bounce、cubic-bezier の第 4 引数 1.3 以上 | 装飾だけの動き、跳ね返り、明滅 | 「読み込みの明滅は 1 か所。150ms 待ってから 300ms 保つ」 |
| 番号 | 見出しの 01、02、03 | 順番の無い内容に番号を振る | 「手順の画面で、順番そのものが内容」 |
| 角丸 | border-radius が 6 か所以上すべて同じ値 | 均一な角丸は部品の役割を消す | 「2 段を使い分けている」 |
| 影 | shadow-md 以上の utility が 4 か所以上すべて同じ | 1 光源の比率になっていない | 「層の数に応じて 2 段」 |
| 書体 | font-family が Inter、Roboto、Arial、system-ui だけ | 既定の書体を理由なく使う | 「製品全体が Inter。他の画面と揃える」 |
| レイアウト | grid-cols-3 | 3 枚のカードの型 | 「候補が 3 つで、比べる用事」 |
| 文言 | Get Started、Learn More、詳しく見る が 3 回以上 | 汎用の CTA の文言 | 「依頼の言葉の表に合わせた」 |

## 3. 帯と判定

件数を帯に写し、clean だけを通す。1 件で落とさないのは、意図して選んだ既定が必ず 1 つはあるからである。帯の区分は pixelslop（AI らしさの検出道具）の区分を借りている。

| 帯 | 件数 | 監修の扱い |
|---|---|---|
| clean | 0〜1 | 通る |
| mild | 2〜3 | 差し戻し。既定との差の表に理由を足すか、直す |
| sloppy | 4〜6 | 差し戻し。計画書に戻って方向から見直す |
| terminal | 7 以上 | 差し戻し。計画書が無いか、読まれていない |

## 4. 誤検出の扱い

機械は件数しか数えられない。Inter も白地も角丸も、意図して選べば正しい。誤検出は理由で外し、理由の無いものだけを数える。

| 場面 | 扱い |
|---|---|
| 依頼が既定を名指しした | 従う。計画書の「既定との差」に「依頼による既定」と書き、置き場を 1 か所に限り、代案を 1 つ添える |
| 製品の既存のブランド色が既定色と同じ | 理由を書いて件数から外す。他の軸で差を作る |
| 見本やテストの fixture | 検査の対象から外す。`node_modules` は常に対象外 |
| 動きの明滅が読み込み表示 | 150ms 待ってから出し、300ms 保つなら理由を書いて外す |
