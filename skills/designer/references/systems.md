# 数値の体系と WCAG 2.2 AA の見た目側

> **3 行でわかる要約**
> 1. 書体・色・余白と密度・動きの 4 つの体系を数値で持ち、見た目側の WCAG 2.2 AA の 10 項目を、計画書で書く値と確かめ方にした文書である。
> 2. 下限は好みではなく標準で決める。文字は 4.5 対 1、部品は 3 対 1、文字の大きさは 12px 以上である。押せる領域は PC で 24px、片手で 44px である。動きは画面の型で分かれ、没入の型（世界観と演出を先に決める型）だけが 4 節の区分の枠を使う。
> 3. 数値には出典のあるものと社内の決めごとがある。表で分けて書き、出典の無い数値を出典つきに見せない。

## 1. 型（書体）

書体は 1 家族 2〜3 役にし、階層は大きさと太さで作る。細い字と小さい字は長時間の作業で疲れる。

| 項目 | 値 | 出典か社内の決め |
|---|---|---|
| 役 | 本文、見出し、数字（等幅）の 2〜3 役。4 役以上は理由を書く | 社内の決め |
| 大きさの段 | 12、14、16、20、24px | 社内の決め（Material 3 の type scale を参考に 5 段へ） |
| 題字（没入の型だけ） | 32〜96px。場面の題だけに使い、本文の下限 12px は変えない | 社内の案（2026-11-26） |
| 下限 | 補助の文字 12px。Apple の最小は iOS で 11pt、macOS で 10pt | Apple HIG、社内の決め |
| 太さ | 400 と 700 を主にする。300 以下は使わない | Apple HIG（細い太さを避ける） |
| 行間 | 1.5 | 社内の決め（WCAG 1.4.12 の間隔の試験にも耐える） |
| 数字 | 等幅数字（font-variant-numeric: tabular-nums） | Vercel の指針、Rauno Freiberg の指針 |

## 2. 色

色は知覚的に均等な色空間（Lab か LCH）で段を作り、段の差でコントラストを保証する。目で合わせた色は、色相ごとに明るさの感じ方がずれる。

| 項目 | 値 | 出典か社内の決め |
|---|---|---|
| 名前つきの色 | 4〜6 色。残りは導出（color-mix）で書く | 社内の決め（Linear は 3 変数からテーマを生成） |
| 本文の文字 | 4.5 対 1 以上 | WCAG 2.2 の 1.4.3 |
| 部品、大きい文字、焦点の枠 | 3 対 1 以上 | WCAG 2.2 の 1.4.11 |
| 装飾の線 | 対象外。ただし行の区切りは罫線に頼らない | WCAG 2.2 の 1.4.11 |
| 計算 | WCAG 2 の式で計算し、目で判定しない。`skills/designer/scripts/contrast-check.sh` | WCAG 2.2、Stripe の配色の記事 |
| ダーク版 | 反転ではなく、同じ名前を暗い側の色で上書きし、全組を計算し直す | 社内の決め |
| 強制カラー | 焦点の枠と印は outline と border で描く。box-shadow は消える | MDN の forced-colors |

## 3. 余白と密度

余白は 4px の倍数、密度は用事で決める。情報の塊は 1 画面に 7 つ以内に収める。

| 項目 | 値 | 出典か社内の決め |
|---|---|---|
| 余白の単位 | 4px の倍数（4、8、12、16、24） | 社内の決め |
| 表の行高 | 32〜40px。14px の文字なら 36px | 社内の決め |
| 情報の塊 | 1 画面に 7 つ以内 | 社内の決め |
| 角丸 | 2 段（部品 4px、面 8px） | 社内の決め |
| 影 | 1 光源で同じ比率の層。色は背景の色相で染める | Josh Comeau の影の記事 |
| 固定の帯 | scroll-padding で焦点を隠さない | WCAG 2.2 の 2.4.11 |

## 4. 動き

動きの決まりは、画面の型で分かれる。今の型と既存に合わせる型は 4.1 節のままで、没入の型だけが 4.2〜4.5 節の決まりを使う。型は依頼者がプロジェクトごとに 1 回決め、デザイナーは計画書に写すだけで選び直さない。

### 4.1 今の型と既存に合わせる型

動きは意味のある場面だけに置き、キーボード起点と高頻度の操作は動かさない。時間と曲線はトークンで持ち、既存に合わせる型では既存の時間と曲線だけを使う。

| 項目 | 値 | 出典か社内の決め |
|---|---|---|
| 長さ | 300ms 未満。段は 80、120、180ms | Emil Kowalski（300ms 未満）、社内の決め（段） |
| 曲線 | 入りは ease-out。標準は cubic-bezier(0.2, 0, 0, 1) | Emil Kowalski、Material 3 の standard |
| 出る動き | 入りより短くする | 社内の決め |
| 動かす属性 | transform と opacity だけ。transition に all は使わない | Emil Kowalski、Vercel の指針 |
| 減らす設定 | prefers-reduced-motion で全部 0ms か不透明度だけ | MDN、WCAG 2.2 の 2.3.3（AAA だが社内で採る） |
| キーボード起点 | 0ms | Rauno Freiberg の指針 |
| 読み込み表示 | 150ms 待ってから出し、300ms は消さない | Vercel の指針 |

既存に合わせる型では、既存の UI の値を `scripts/fidelity-check.sh --inventory <既存の UI の置き場>` で棚卸しの表にし、計画書の「## 既存の値」の節に写す。棚卸しの表は、色・時間・大きさ・書体の値と出現数を並べたものである。足す値は計画書の「足す値」の表に 1 行ずつ理由と書く。計画書の検査は、名前つきの色・動きの長さ・書体と字の大きさを棚卸しの表と突き合わせ、新しい色 4〜6 色と既定との差は求めない。実装のあとは `fidelity-check.sh` に `--existing <棚卸しの表か既存の UI>` を渡し、トークンと実装も突き合わせる。既存に無く、足す値の表にも理由の無い値は、どちらでも落ちる。

### 4.2 没入の型で変える決まり

没入の型で変えるのは次の 9 つだけで、ほかは 4.1 節と同じである。どの行も、世界観の設定と演出計画書（時刻ごとの動きと守りの表）に書いた動きにだけ当てる。

| 今の決まり | 没入の型での扱い | 条件 |
|---|---|---|
| 動きは 300ms 未満 | 応答は 80〜200ms（今の型の 300ms 未満より短い枠）。移動と見せ場（世界に入る場面の長めの演出）は、4.3 節の枠を使える | 枠を超えた行は、計画書の検査が落とす |
| 動かすのは transform と opacity だけ | 見せ場に限り、filter と clip-path と canvas 1 枚を使える | 同時に動くレイヤーは 4 つまで、ぼかすレイヤーは 1 つまで。フレームが落ちたら短い版に替える |
| 装飾だけの動きは禁止 | 世界観の設定に役目を書いた動きは使える | 役目は、場所・状態・感情のどれを伝えるか。役目を書けない動きは、今までどおり却下 |
| キーボード起点は 0ms | 見せ場と移動は、キーで起こしても流す。応答は今のまま 0ms | どのキーでも飛ばせる。先に打った字を失わない |
| 曲線は 1 つ | 標準・去る・着く・収まるの 4 つ | 行き過ぎて戻る「収まる」は、収まりの 1 要素だけ |
| 記憶に残す要素は 1 つ | 画面の印は 1 つのまま。見せ場を場面ごとに 1 つ足せる | 見せ場ごとに共有要素（前の場面から付いて来る部品）を 1 つ名指す |
| 方向は 1 案で伺う | 方向を 3 案、静止画 1 枚ずつで並べ、依頼者が 1 つ選ぶ | 色と書体は、選ばれた案で決める |
| 承認の点は 4 つ | 5 つ目に見せ場を足し、動くサンプルで伺う | 最初のサンプルは 1 場面だけ |
| 監修は値の突き合わせで、撮影は任意 | 100ms ごとのフレームの一覧を必ず撮り、計画との差をフレームと値で書く | `references/review-method.md` の 6 節 |

変えない決まりは、コントラスト（文字 4.5 対 1、部品 3 対 1）と文字の 12px、動きを減らす設定の版である。transition の all の禁止と、実装にトークンの外の値を残さない決まりも同じである。初期表示の JS の 170KB も今のままで、演出のアセットは遅れて読み、別の枠（圧縮後 600KB）で数える。枠を決めるのはフロントエンドである。

### 4.3 動きの 4 つの区分と長さの枠

動きの長さは、1 つの上限ではなく、起きる頻度で 4 つの区分に分ける。毎秒起きる応答は短いままにし、長さを使えるのは、1 回の利用で数回の見せ場だけである。数値は案で、最初のサンプルを測って決め直す。

| 区分 | 何の動きか | 長さの枠（案） | 入力の扱い |
|---|---|---|---|
| 応答 | 押し込み、ホバー、フォーカスの移り | 80〜200ms。キーボード起点は今のまま 0ms | 入力を止めない。押してから 100ms 以内に最初の変化を出す |
| 移動 | 一覧から詳細、タブの切り替え | 240〜500ms | 途中で次の操作を受ける |
| 見せ場 | 起動、スタートからログインへ、ログインの成功 | 初回 600〜1,400ms。2 回目から 600ms 以下 | どのキーでも飛ばせる |
| 環境 | 背景の粒子、光のゆらぎ | 周期 4 秒以上で、動く量は小さく | 止める手段を置く |

「PS5 のゲームのような」という依頼は、次の 4 つの性質と読む。参照の作品と場面を依頼者から受け取ったら、そちらを正にする。PS5 の本体のメニューの長さや曲線を公開した一次情報は、見つかっていない。

| 性質 | 中身 | 受け持つ演出の型 |
|---|---|---|
| つながる | 押した物が、次の場面まで付いて来る | 共有要素 |
| 奥行がある | 奥と手前が、違う速さで動く | 視点の移動 |
| 緩急がある | 動きに、入りと見せ場と収まりがある | 幕、重ね |
| 生きている | 何もしない間も、画面が小さく動く | 環境、焦点の移り |

「ただスライドさせる」に戻らないように、演出の型を 6 つ持つ。移動では、共有要素か 2 つ以上のレイヤーを持たせる。

| 演出の型 | 中身 | 使う区分 |
|---|---|---|
| 共有要素 | 押した物や選んだ物が、消えずに次の場面の一部になる | 移動、見せ場 |
| 視点の移動 | 画面の全体が進み、レイヤーが違う速さで動く | 見せ場 |
| 幕 | 押した点から形が開いて、次の場面が現れる | 見せ場 |
| 重ね | 部品が役目の順に、40〜80ms ずつずれて現れる | 移動、見せ場の収まり |
| 焦点の移り | フォーカスの光が、次の対象へ動いて届く | 応答 |
| 環境 | 背景が小さく動き続ける | 環境 |

### 4.4 見せ場の 5 つの条件

見せ場は、次の 5 つを満たすものだけを通す。この 5 つが「ただスライドさせるんじゃない」を機械で見る基準で、`scripts/motion-plan-check.sh` が演出計画書の表から確かめる。

| 条件 | 中身 | 演出計画書のどこで見るか |
|---|---|---|
| 段が 3 つ | 入り（押した合図）、見せ場（場面が動く）、収まり（部品が落ち着く） | 時刻ごとの表の段の列。入りは押してから 100ms 以内に始める |
| レイヤーが 3 つ以上 | 奥・中・手前が、違う速さか違う時刻で動く | レイヤーの表と、時刻ごとの表のレイヤーと対象の列 |
| 共有要素が 1 つ | 前の場面の部品が、次の場面まで付いて来る | 表題の下の表の共有要素と、時刻ごとの表の 2 行以上 |
| 動きが重なる | 前の動きが終わる前に、次の動きが始まる組が 1 つ以上ある | 時刻ごとの表の時刻と長さ |
| 守りが 5 行 | 動きを減らす設定、飛ばす手段、2 回目以降、アセットが間に合わないとき、終わりのフォーカス | 守りの表の上の 5 行 |

同じ検査は、時刻ごとの表の長さがトークンの表の外に出ていないことも見る。初回が 600〜1,400ms に収まり、2 回目以降が 600ms 以下であることも確かめる。

### 4.5 守り

守りは、演出ごとに必ず書く代わりの版と手段である。上の 5 行は見せ場の条件で、下の 3 行は没入の型で足す守りになる。下の 3 行の出典は WCAG 2.2 のレベル A の達成基準で、本文はまだ開いておらず、確かめる段取りは付録に書いた。

| 守り | 決まり | 出典か社内の決め |
|---|---|---|
| 動きを減らす設定 | 位置と大きさを動かさない版を持つ。見せ場は 150ms 前後の溶け込みに替え、終わりの状態は同じにする | MDN、WCAG 2.2 の 2.3.3（AAA だが社内で採る） |
| 飛ばす手段 | どのキーとどこを押しても、すぐ最後の状態へ進む。先に打った字を失わない | 社内の案（計測の合格の線は 300ms 以内） |
| 2 回目以降 | 同じ利用の中の 2 回目からは、600ms 以下の短い版にする | 社内の案 |
| アセットが間に合わないとき | 押してから 100ms 以内に、共有要素だけは必ず動かす。残りは短い版に替える | 社内の案 |
| 終わりのフォーカス | 演出の終わりにフォーカスを入れる要素と、読み上げに伝える題を決める | 社内の案 |
| 5 秒を超える動き | 自動で始まり、5 秒を超えて続く動きには、止める操作を置く | WCAG 2.2 の 2.2.2（レベル A） |
| 点滅 | 明るさの大きな切り替わりは、1 秒に 3 回まで | WCAG 2.2 の 2.3.1（レベル A） |
| 音 | 最初の版は音を入れない。入れるときは、消音の操作を常に画面に置く | WCAG 2.2 の 1.4.2（レベル A）、社内の案 |

没入の型の検査と撮影は、まず Web の画面だけを対象にする。アプリ（iOS など）には世界観の設定と演出計画書の書き方だけを使い、検査を次の段階で足す。

## 5. 見た目側の WCAG 2.2 AA

見た目で決まる達成基準を 10 項目にし、計画書で書く値と確かめ方を揃える。振る舞い側（拡大、リフロー、読み上げ、時間切れ、ステータスメッセージ）は画面仕様で見る。

| 達成基準 | 計画書で書く値 | 確かめ方 |
|---|---|---|
| 1.4.1 色の使用 | 色だけで伝える要素の数（0） | 白黒で印刷して読める |
| 1.4.3 コントラスト（最低限） | 文字の全組の最小の比 | `contrast-check.sh` |
| 1.4.11 非テキストのコントラスト | 部品と焦点の枠の比 | `contrast-check.sh` |
| 1.4.12 テキストの間隔 | 間隔を広げて欠ける要素の数（0） | 間隔を変える CSS を当てる |
| 1.4.13 ホバーまたはフォーカスで表示されるコンテンツ | Esc で消え、乗せても消えず、焦点を外すまで残る要素の数 | 要素ごとに 3 条件を試す |
| 2.1.4 文字キーのショートカット | オフにできる 1 文字キーの数 | 設定を切ってキーを押す |
| 2.4.7 フォーカスの可視化 | 枠の見えない要素の数（0）。outline で描く | Tab で全要素を通す。強制カラーでも見る |
| 2.4.11 フォーカスの非遮蔽（最低限） | 固定の帯に隠れる要素の数（0） | 帯の近くの要素に Tab で入る |
| 2.5.8 ターゲットのサイズ（最低限） | 最小の押せる領域（PC で 24px、片手で 44px） | DOM の寸法を測る |
| 2.3.3 動きの抑制（AAA。社内で採る） | 減らす設定で残る動きの数（0） | 設定を有効にして全場面を見る |

## 6. 押せる領域の決め

押せる領域は、入力の手段で下限を分ける。WCAG 2.2 の 2.5.8 の 24px は AA の下限で、Vercel の指針も PC では 24px、モバイルでは 44px を求める。

| 画面 | 下限 | 理由 |
|---|---|---|
| PC のポインタ前提の画面 | 24px 四方 | WCAG 2.2 の 2.5.8 と Vercel の指針 |
| 片手で使う画面（スマートフォン） | 44px 四方 | Apple HIG と Vercel の指針 |
| 両方で使う画面 | 幅で切り替える。狭い幅で 44px | 社内の決め |
