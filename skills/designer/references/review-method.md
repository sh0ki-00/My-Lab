# 監修の方法

> **3 行でわかる要約**
> 1. 実装された画面を計画書に照らして監修する方法を決めた文書である。5 観点（忠実度・AI らしさ・WCAG 2.2 AA・キーボード・動き）と、許容差と判定の 3 択を書く。
> 2. 計画が判定基準であり、感想で差し戻さない。値は機械で突き合わせ、指摘は場所・計画の値・実装の値・直し方・重さの 5 欄で書く。没入の型（世界観と演出を先に決める画面の型）では、100ms ごとのフレームの一覧を必ず撮り、計画との差をフレームと値で書く（6 節）。
> 3. 監修は実装した本人がしない。秘書が別のサブエージェント（別の文脈で動く補助の AI）か新しいチャットで回す。

## 1. 5 観点と道具

監修は 5 観点を順に見る。道具で測れるものは道具で測り、人の目は道具が拾えない所に残す。

| 観点 | 何を見るか | 道具 |
|---|---|---|
| 忠実度 | 計画書の色・ms・px とトークンと実装の値の一致 | `skills/designer/scripts/fidelity-check.sh` |
| AI らしさ | 既定の見た目の件数と帯 | `skills/designer/scripts/ai-look-check.sh --plan <計画書>` |
| WCAG 2.2 AA | 見た目側の 10 項目の実測 | `skills/designer/scripts/contrast-check.sh`、Tab の通し、DOM の寸法 |
| キーボード | 計画のキーの表の全行が動くか | 手で通す。Playwright（ブラウザ操作の自動テスト）があれば記録 |
| 動き | 場面ごとの ms、減らす設定、キーボード起点 | 今の型と既存に合わせる型は、画面を撮るか DOM の transition の値を読む。没入の型は 100ms ごとのフレームの一覧（6 節） |

AI らしさと動きの観点では、道具が数えない次の 2 行も、監修者が見て数える。出どころは、動きの手引き（`references/ai-look-catalog.md` の出典 6）である。

| 見ること | 中身 | 数え方 |
|---|---|---|
| 全区画の現れ | どの区画もスクロールで同じに浮くか。読む順と関係なく同じ動きなら、AI の既定に数える | 区画ごとにスクロールして撮り、フレームで数える |
| ホバーの子要素 | 押せる物そのものを動かさず、子要素だけが動くか。押せる物が薄くなるだけのホバーは、手応えが無い | 押せる物ごとにホバーして、動いた要素を DOM とフレームで見る |

## 2. 突き合わせるものと許容差

値の突き合わせは許容差を先に決める。色は 0、px は ±2、ms は ±20 で、差の重さは場所で決める。

| 突き合わせるもの | 許容差 | 重さの決め方 |
|---|---|---|
| 名前つきの色、導出の色 | 0（16 進が一致） | 本文と地は高、補助と装飾は中 |
| 行高、ペインの幅、帯の高さ | ±2px | 密度に効く行高は高、帯は中 |
| 動きの時間 | ±20ms | 300ms 超（没入の型では区分の枠の外）か、減らす設定の欠けは高。差だけなら低 |
| フレーム（没入の型） | 計画の時刻のフレームに、計画の状態が見える | 共有要素（前の場面から付いて来る部品）が途切れる、動きの最中に字が読めない、終わりの状態が静止の画面とずれる、の 3 つは高 |
| 角丸、影 | 段の数が一致 | 均一になっていれば中 |
| シグネチャ | 要素があり、伝える情報が出る | 無ければ高 |
| 焦点の枠 | outline で描き、2px 以上 | box-shadow だけなら高（強制カラーで消える） |

## 3. 手順

手順は 9 つで、終わりの印を持つ。撮れない環境では DOM の値で代える。

| # | 手順 | 終わりの印 |
|---|---|---|
| 1 | 計画書とトークンを読み、突き合わせる値の一覧を作る | 一覧がある |
| 2 | `fidelity-check.sh` で 16 進と ms を突き合わせる | 差の表がある |
| 3 | `ai-look-check.sh --plan` を実装に回す | 件数と帯がある |
| 4 | 5 状態ごとに画面を見る（撮れるなら撮る） | 5 状態 × 画面の表がある |
| 5 | AA を測る（比の計算、焦点、固定の帯、押せる領域、強制カラー） | 10 項目に値がある。没入の型では 2.2.2 と 2.3.1（音があれば 1.4.2）も足す。測れない項目は未確認の表に理由と確かめ方を書く |
| 6 | キーボードで主要な用事を通す | キーの表の全行に結果がある |
| 7 | 動きを確かめる（ms、曲線、減らす設定、キーボード起点）。没入の型では、6 節のフレームの一覧を撮って見る | 動きの表の全行に結果がある。没入の型ではフレームの所見の表がある |
| 8 | 指摘の表と判定を書く | 全指摘に 5 欄がある |
| 9 | `review-check.sh` と `tools/check-file.sh` を通し、秘書に返す | 両方 PASS |

## 4. 判定の 3 択

判定は 3 択で、条件には確認方法と期限を書く。感想の指摘（「もっとおしゃれに」）は書かない。計画書が無い画面は、先にデザイナーが計画を書いてから監修する。

| 判定 | いつ | 書くこと |
|---|---|---|
| 受け入れ | 差 0、帯 clean、AA の 10 項目が充足、キーと動きが全行一致 | 測った値 |
| 条件つき受け入れ | 重さ「中」以下の指摘だけ | 条件、確認方法、期限 |
| 差し戻し | 重さ「高」の指摘が 1 つ以上 | 指摘の表と直し方 |

監修者は実装を直さない。直すのは実装した担当で、監修者は指摘の表に直し方を書いて返す。監修の途中で監修者が直してしまったときは、その指摘を重さのまま表に残し、直した人を書く。直した分は、別の監修者が撮り直したフレームと値で確かめるまで受け入れに数えず、高の指摘なら判定は差し戻しのままにする。

## 5. 撮れない環境

Claude Code のデスクトップ版はブラウザの画面を撮れるが、Cursor は環境に依る。撮影は、今の型と既存に合わせる型では任意にし、機械検査と DOM の値を必須にする。没入の型の動きだけは、撮影を DOM の値で代えない（6 節）。

| 見たいもの | 撮れないときの代わり |
|---|---|
| 密度と配置 | 行高、ペインの幅、塊の数を px と個数で計画書と突き合わせる |
| 焦点の枠 | DOM の outline の値と、Tab で焦点が移る要素の一覧 |
| 動き | DOM の transition と animation の値、prefers-reduced-motion の分岐の有無 |
| 5 状態 | 状態ごとの DOM の文字列（空の文、エラーの 2 文） |

## 6. 没入の型: フレームを見て直す

没入の型では、動きを値の突き合わせだけで受け入れない。100ms ごとのフレームの一覧を必ず撮り、計画との差をフレームと値で書く。AI はコードから動きの良し悪しを見られないので、見る手順を省くと、値は合っているのにぎこちない演出が通るからである。見るのは見せ場（世界に入る場面の長めの演出）で、比べる計画は演出計画書（時刻ごとの動きと守りの表）にある。

| 撮るもの | 撮り方 | 見ること |
|---|---|---|
| 初回の見せ場 | 押した時刻を 0ms とし、終わりのフォーカスまで 100ms ごとに撮る | 段・レイヤー・共有要素・重なりが、演出計画書の時刻にあるか |
| 2 回目以降 | 同じ操作をもう一度して撮る | 短い版の長さと、残した動き |
| 動きを減らす設定 | 設定を有効にして、同じ操作で撮る | 位置の動きが 0 で、終わりの状態が同じか |
| 飛ばしたとき | 途中でキーを押して撮る | 最後の状態に進み、フォーカスが決めた要素にあるか |
| 静止の画面 | 終わってから 1 枚撮る | 最後のフレームとの差が 0px か |

フレームは時刻を止めて進めながら撮るので、何度撮っても同じ絵になる。撮るのはフロントエンドで、道具は計測と同じ `skills/frontend/scripts/motion-measure.sh` の `--frames <置き場>` である。初回と 2 回目以降は 100ms ごと、動きを減らす設定は始まり・半ば・終わり、ほかに静止の画面と飛ばしたときを 1 枚ずつ撮り、一覧を frames.json に残す。コマンドは `bash skills/frontend/scripts/motion-measure.sh --config tmp/flow/<件名>/motion-measure.json --frames tmp/flow/<件名>/frames` で、デザイナーは撮れたフレームを見る。監修記録の対象の表には、フレームの一覧の置き場と、撮った条件を書く。`review-check.sh` は、没入の型の監修記録にこの行とフレームの所見の表が無いと落とす。

所見は時刻ごとに 1 行で、計画・見えたもの・直し方・重さを書く。感想（「もっと滑らかに」）は書かず、どのフレームのどの値かを書く。次の表は、架空の見せ場「潜る」の 1 回目の実装への所見の例である。

| フレーム | 計画 | 見えたもの | 直し方 | 重さ |
|---|---|---|---|---|
| 100ms | 灯が 0.96 倍に沈み、光が集まる | 灯は沈んだ。光の輪が出ていない | 輪の不透明度を `--duration-2` で 0 から 0.6 にする | 中 |
| 600ms | 灯が弧の途中にある | 灯がまっすぐ動いている | 弧にする。まっすぐでは差し替えに見え、同じ灯と読めない | 高 |
| 1,000ms | 計器盤が下から上がる | 上がる途中の字が、地と 2.9 対 1 | 字は、計器盤の不透明度が 1 になってから出す | 高 |
| 1,400ms | 入力欄にフォーカス。静止の画面と同じ | 差は 0px。フォーカスは 1 つ目の入力欄 | なし | なし |

没入の既定（`references/ai-look-catalog.md` の 5 節）も、フレームの一覧で数え直す。機械の印で拾えない手書きの粒子や、名前の違う浮き上がりがあるからである。撮れないときは、受け入れにも条件つき受け入れにもしない。判定は差し戻しにし、撮れない理由と撮る手段を指摘の表に書く。
