# 6 本の柱と、層・権限・秘密・暗号化・監査ログの決め方

> **3 行でわかる要約**
> 1. インフラ構成設計書の 6 本の柱と、守りの 5 つの決めの基準をまとめた資料です。5 つとは 3 層・最小権限・秘密の置き場・暗号化・消せない監査ログです。
> 2. 基準は AWS Well-Architected と CIS の基準で、決めごとに測り方を 1 つ置き、測れない決めは書きません。
> 3. 設計書の該当の節を書くときに開き、表の行を写してから題材に合わせて直してください。

## 6 本の柱

この節は、設計書の「6 本の柱」の表に入れる観点と、測り方の例を並べます。柱の名前は AWS Well-Architected（AWS の設計の点検の枠組み）に合わせました。

| 柱 | 決めること | 測り方の例 |
|---|---|---|
| 運用の上手さ | 変更の出口をコードと CI に限る。計画の置き換えと削除で止める | 人の手による書き込みの数、iac-scan の結果 |
| セキュリティ | 3 層の分離、最小権限、秘密の置き場、暗号化、消せない監査ログ | iac-scan と trivy（構成にある既知の穴を探す道具）の件数 |
| 信頼性 | ゾーンの数、自動の切り戻し、復元の頻度 | SLO（成功率などの目標）、復元の実測の秒 |
| 性能の効率 | 応答の目標、自動で増やす条件 | 応答時間の 99 パーセンタイル |
| 費用の最適化 | 常時の大きさ、増やす上限、検証環境の小ささ | 月の請求と費用の幅の差 |
| 持続可能性 | 小さな資源、ARM、ログの保持の日数 | vCPU の時間、ログの GB |

## ネットワークの 3 層

この節は、層ごとに置くものと、受けてよい通信を決める基準です。層の間は、セキュリティグループ（資源ごとの通信の許可の表）で相手を名指しします。

| 層 | 置くもの | 受けてよい通信 | 外へ出る道 |
|---|---|---|---|
| 公開の層 | 配信、WAF、公開のロードバランサー | 利用者の HTTPS | 次の層の入口だけ |
| アプリの層 | API、内部のロードバランサー | 公開の層の入口から | データの層と、VPC エンドポイント |
| データの層 | データベース、キャッシュ | アプリの層から | なし |

管理の口（22、3389、5432 など）を 0.0.0.0/0 に開けません。人がデータベースに入る道は、承認つきの一時の接続だけにします。外への道は NAT ではなく VPC エンドポイントにし、依存部品が乗っ取られたときの持ち出しを防ぎます。

## 最小権限の IAM

この節は、権限の表の書き方です。主体ごとに、許す操作と対象を名指しします。

| 決まり | 具体的には |
|---|---|
| 「*」を書かない | 操作も対象も名指しする。対象を絞れない操作だけ、理由つきの例外にする |
| 長期のアクセスキーを作らない | CI は OIDC、人は IAM Identity Center の一時の資格 |
| 役割を分ける | 起動の役割と実行中の役割、押し込みと適用を分ける |
| 広い管理の方針を付けない | AdministratorAccess と PowerUserAccess を役割に付けない |

## 秘密の置き場と暗号化

この節は、秘密と鍵の基準です。秘密は保管庫に置き、値はコード・変数・状態のどこにも書きません。

| 項目 | 基準 |
|---|---|
| 置き場 | Secrets Manager か、データベースが自分で作って預けるパスワード |
| 回転 | 自動で回せるものは自動。回せないものは日数と担当を書く |
| 接続 | データベースへはパスワードではなく、短く切れる IAM の認証の札で入る |
| 保存時の暗号化 | データベース、バックアップ、バケット、ログ、イメージの全部 |
| 通信時の暗号化 | 利用者まで TLS 1.2 以上、データベースも TLS を強制する |
| 鍵 | 用途ごとに分け、年 1 回の自動の回転を入れる |

## 消せない監査ログ

この節は、監査ログを「消せない」と言える条件です。管理者の権限でも消せないことが条件で、権限で守るだけでは足りません。

| 条件 | 具体的には |
|---|---|
| 全地域の操作を取る | CloudTrail を全地域にし、ファイルの改ざんの検知を入れる |
| 消せない置き場 | オブジェクトロックを COMPLIANCE の型で掛け、保持の日数を書く |
| 人の書き込みに気づく | 本番のアカウントで人が書き込んだら、SRE に通知する |
