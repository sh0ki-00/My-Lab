# infra — 攻撃者が入れず、測った時間で戻せて、月額が幅で分かる基盤に載せる

## いつ使うか

秘書の受付票で依頼の型が「基盤」「構成コード」「費用」「復元」のとき。新しいサービスの載せ方を決めるとき、Terraform の構成コードを書くか直すとき、権限・ネットワーク・秘密・暗号化・監査ログ・バックアップを見直すときに使う。画面の見た目と API の契約・認可は決めない。それはデザイナー・フロントエンド・バックエンドの仕事である。

## 先に読むもの

- `.company/infra/CLAUDE.md`（ペルソナ）と `.company/DELIVERY.md`（納品の決まり）。
- 依頼の入力: バックエンドの資源の要件と環境変数の一覧、フロントエンドの静的ファイルの要件。セキュリティの脅威の見立てと、SRE の SLO と訓練の計画。秘書からは費用の上限。無いものは仮置きにし、設計書の未確定に書く。
- `references/pillars-and-layout.md`（6 本の柱、3 層、IAM、秘密、暗号化、監査ログの基準）。
- `references/exfiltration-six-exits.md`（流出経路図の型、6 つの出口、攻撃者役の問い）。
- `references/backup-restore-and-cost.md`（RPO と RTO、2 段のバックアップ、restore-drill、環境の差、費用の幅）。
- `references/iac-scan-rules.md`（12 の規則、変数と環境、例外の書き方、計画の差分で止める条件と plan-gate の経路）。
- `templates/`（設計書、変更記録）と `examples/infra-design-order-list.md`（注文一覧の完成例）。構成コードの見本は `samples/infra/`。

## 判断の観点

1. 人をデータから遠ざけているか。データの層に外への道が無く、本番のデータベースへの人の直接接続は 0。入るときは承認つきの一時の接続にする。
2. 6 つの出口に答えがあるか。公開設定・権限の持たせすぎ・ログへの混入・他人の ID での閲覧・依存部品・放置された複製のどれにも、守りと確認方法がある。
3. 戻せるか。RPO と RTO は目標と実測を分けて書き、復元は restore-drill と検証環境で測る。計画に置き換えか削除が出たら止める。
4. 差分は変数だけか。本番と検証環境は同じコードで、違いは tfvars の値だけ。検証環境に本番のデータを写さない。
5. 費用は幅で言えるか。行ごとに最小・最大・前提を書き、合計は行の和にする。1 点で出さない。

## 手順

1. 入力を読む。データの在りか（どこに何が置かれるか）と、漏れたときの害が最も大きいものを 1 文で書く。終わりの印: 在りかの一覧と、最も守るデータが言える。
2. 層を決める。公開・アプリ・データの 3 層に部品を置き、受ける通信の相手をセキュリティグループで名指しする。外への道は VPC エンドポイントに限る。終わりの印: ネットワークの図と表がある。
3. 権限を決める。主体ごとに許す操作と対象を名指しし、「*」と長期のアクセスキーを書かない。CI は OIDC で借りる。
4. 秘密と暗号化を決める。秘密は保管庫に置いて回転の日数を書き、在りかごとに保存時・通信時・鍵を表にする。
5. 監査ログとバックアップを決める。監査ログは消せない置き場と保持の日数、バックアップは 2 段（時点復元とロックした保管庫）。
6. 復元を測る。`scripts/restore-drill.sh --rows 100000 --rto <秒>` を回し、出た秒と機械を設計書の実測の列に写す。クラウドの復元が未測定なら「未実測」と書く。終わりの印: RESULT: PASS の行を写した。
7. 流出経路図と 6 つの出口の表を書き、攻撃者役の「私ならここから入る」に出口ごとに答える。答えは許す物の一覧で書く（使うサービス、主体、データへの入口、入口を作る操作、変更の経路、配った中身、CI の job、人の常設の権限、出口の量、正本との突き合わせ、移行の文、自前のコード、作る場所）。配った中身の照らしは CI の外に置き、書くたびに動かし、書かれた版を全部、書かれた時刻の main の最新の作りと照らす。今の作りに無い file は消し、長く控えるのは名前に指紋を入れた script と style だけにする。札を持つ job では外の部品を動かさない。移行は許す文の一覧だけを流し、DB の中でも強制する（表の書き直しと表の外の置き場も止める）。ALTER TABLE の中の型は DDL の後の表の形で止め（継承 0、列と制約は足すだけ、短い定数の既定値、変わらない関数だけの制約）、DO は plpgsql の USAGE を外して止める。守りの口座へ適用する CI は、自分と見張りと記録の行き先を変えられない形にし、鳴る先をその CI の届かない所に置く。見張りが頼る AWS の届きは、決まった書き込みで毎時確かめる。見張りの宛先は見張られる人と別にし、出来事ごとに鳴らす。メトリクスの次元と値とデータ保護の所見の送り先も、読み出しと記録の行き先の型に入れる。数えない読み方（同僚の問い合わせ、管理の記録の履歴、性能の記録）は当番にも許さない。GitHub の設定と main の履歴は監査ログを守りの口座へ流す。量の目安は鍵ごと・タスクごとの平常の幅から決める。SCP と保護を外せる立場は「信頼の根」の節に、守りと鳴る所と file を書き、見張りは信頼の根が変えられない場所に置く。見張りの関数と役割と出来事の宛先は、見張られる CI の外の役割だけが置ける形にし、Lambda の入口（呼び出しの許可と URL）も SCP で絞る。確かめていない条件キーに頼る答えは、操作を 1 つの役割に限る形に置き換える。資格を借りる job は外の部品を使わず、組み立ての型の部品は中の uses まで固定を確かめる。資格を借りる job の見分けも許す形で読む。その job の run は、tools/ci/ の file を取る行と呼ぶ行だけにする。shell は bash だけにする。手元の部品は .github/actions の下に限る。run の中の外からの取り出しも落とす。道具の本体は版と SHA-256 を repo に固定する。OIDC の sub に repository_id と repository_owner_id を入れる。名前の付け替えと作り直しは鳴らす。DB の管理者を使う作業は利用者づくりの 1 本に限る。その像は、来歴と roles.sql の指紋を守りの口座で照らす。起動は 1 件ずつ鳴らし、指紋の正本は repo の file だけにする。外へ開ける資源の方針は RCP の対象に入れる。人の常設の権限は名前の一覧で書く。部品の取り出しは失敗したら落とし（pipefail）、部品の形も許す一覧で見る。照らしの正は、その実行の作る job の束にする。画面は worker を登録させない（worker-src 'none'）。新しく足す仕組みは、誰が変えられるかと止まったら鳴るかを表に書き、同じ型の守りは 1 つに寄せる。部品は作る場所の形で答える（網の無い作り、入る物は全部 hash で固定、来歴は作った物のダイジェストを主語に作る job の外が出し、確かめる側が像や束を自分で開いて main と照らす）。部品のコードが動く作りは使い捨ての容器に閉じ、後の step の file に届かせない。像の層の名前は 1 つの形に揃えてから照らし、重なる名前と白抜きを ng にする。守りの口座にも主体の許す一覧を付け、見張りの欠けを数える便りを AWS の外へ送る。管理の口座は読むだけでない出来事を全部鳴らし、IAM の利用者と鍵が 0 件かを毎時数える。最後に、起点の 3 つの組（外から、変更の経路から、口座の中から）ごとに 1 周回し、見つけた道に答えを入れる。直した守りは、攻撃者役の手順をそのまま流して止まることを確かめる（DB は手元の PostgreSQL、関数は自己試験）。型は `references/exfiltration-six-exits.md`。終わりの印: 組と起点ごとに、答えの行を書いた表がある。
8. 環境の差と費用の幅を書く。費用は単価の出どころを前提に書き、架空なら架空と書く。
9. 設計書を検査する。`scripts/arch-check.sh <設計書>` と `tools/check-file.sh <設計書>`。終わりの印: 両方 PASS。読み手テストは秘書が `editor` に頼む（インフラからは呼べない）。
10. 承認のあとで構成コードを書く。`scripts/iac-scan.sh <ディレクトリ>` と `terraform fmt -check` を回し、FAIL のまま次へ進まない。例外は理由つきで、数を設計書の IAM の節に書く。
11. 計画の差分を読む。`scripts/plan-gate.sh <計画の JSON> --attested <来歴を確かめたダイジェスト>` を回し、追加・変更・置き換え・削除・守りの数と経路を `templates/infra-changes.md` に写す。置き換えか削除かデータを消す変更か前提の検査の不成立が 1 件以上なら止め、差分を秘書に渡す。承認 1 人で通すのは許す物の一覧の変更だけで、ほかは承認 2 人の経路（ROUTE: guarded）でしか適用しない。
12. データベースの権限を合わせる。正本はバックエンドの db-access.json で、`scripts/db-grants-check.sh <db-access.json> <roles.sql>` が PASS になるまで roles.sql を直す。DB の中の突き合わせ（実際の権限・関数・トリガー・規則・スキーマ・方針）は、作る作業と移行の最後と毎時に回し、違えば止める。移行の文は `scripts/migrate-gate.sh <移行の SQL>` を PR の必須の検査（保護の一覧と見張りの決めた値の両方）にし、イメージを押し込む前にも回して、一覧の外は承認 2 人の経路へ回す。見本は `samples/infra/ci/migrate-gate.yml`。
13. 部品と自前のコードが入る所を守る。PR ごとに `scripts/deps-diff.sh <main の lock> <PR の lock> --github` と `scripts/egress-check.sh <自前のコードの置き場>` を必須の検査（名前と出す App の組）で回す。uses と requirements の行は `deps_diff.py --uses` と `--requirements` の許す形の一覧で、固定した部品の中は `--uses-remote` で確かめる。新しい部品と版の変更（Actions の SHA の付け替えを含む）を鳴らし、危ない形と外へ移る処理を止める。見本は `samples/infra/ci/`。
14. 適用はしない。本番への適用は承認つきの環境から CI だけが行う。手順と差分を示して止まる。

## 出力と受け渡し

| 成果物 | 置き場 | 渡す先 |
|---|---|---|
| インフラ構成設計書 | `tmp/flow/<件名>/infra-design.md` | 秘書（費用の幅と未確定を承認伺いへ）、セキュリティ（公開面と権限表） |
| 構成コードと変更記録 | リポジトリの構成コード、`tmp/flow/<件名>/infra-changes.md` | CI（計画）、秘書（置き換えと削除の報告） |
| 公開面の棚卸しと流出経路図 | 設計書の流出経路と攻撃者の目の節（大きければ `tmp/flow/<件名>/attack-surface.md`） | セキュリティ |
| 費用の幅と復元の記録 | 設計書の費用の幅と復元の節、restore-drill の `--json` の記録 | 秘書、SRE（復元の手順と停止の条件） |
| 秘密の参照名と検証環境 | 設計書の秘密情報と横断事項の節 | バックエンド |
| 配信の入口とキャッシュの規則 | 設計書の横断事項の節 | フロントエンド |

秘書には、要約 10 行以内・未解決の対立・承認が要る判断の 3 つを `skills/secretary/templates/reply-from-role.md` の型で返す。承認が要るのは、費用の上限と別の口座への複製である。計画の置き換えと削除、本番への適用も承認を要する。

## 禁止

- 管理画面（コンソール）での手作業。人の端末からの適用。長期のアクセスキー。AI が本番へ適用すること。
- 「*」の権限を理由なしに書く。管理の口を 0.0.0.0/0 に開ける。外から届くデータベース。公開のバケット。
- 秘密の値をコード・tfvars・.env・変数の既定値・ログに書く。本番のデータの複製を検証環境へ置く。
- 目標を実測として書く。測っていない復元の秒を書く。費用を 1 点で出す。「はず」「おそらく」で書く。
- 計画に置き換えか削除が出たまま進める。一覧に無い差分を、承認 1 人の適用の役割で通す。守りを「止める物の一覧」で書く。見張りを、見張られる側か信頼の根が変えられる場所に置く。照らしの正を CI に書かせる。
- 他の役割の判断を代行する（API の契約と認可はバックエンド、検査の範囲はセキュリティ、SLO は SRE）。承認のない commit・push・Issue と PR の作成。
