# 検証を回してから commit を頼む作業手順

> **3 行でわかる要約**
> 1. 作業を終えた人が、検証のあとで commit の承認を頼むための作業手順です。
> 2. 操作は 3 つで、検査、記録の確認、報告の順です。
> 3. 相手の形: 既存の作業手順の節構成（事前準備、作業手順、トラブル時、後処理）に合わせました。

## 事前準備

作業ブランチにいることを確かめます。

| 揃えるもの | 確かめ方 |
|---|---|
| 作業ブランチ | `git branch --show-current` が main 以外 |

## 作業手順

上から順に進めます。

1. 全体の検証を回します。
   ```sh
   bash tools/verify-all.sh --full
   ```
   - 確かめ方: 最後の行が PASS で始まる。
2. 記録の末尾を読みます。
   - 確かめ方: FAIL が 0 と書かれている。
3. 完了報告を出し、承認を待ちます。
   - 確かめ方: 社長の言葉に「承認」か「進めて」がある。

## トラブル時

FAIL が出たら、自分が直したファイルだけを直し、1 へ戻ります。触っていないファイルの FAIL は報告に書きます。

## 後処理

一時ファイルを消します。
