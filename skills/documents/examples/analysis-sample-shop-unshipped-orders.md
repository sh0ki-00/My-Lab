# データ分析: 見本の店で出荷が済んでいない注文はどこで止まっているか

> **3 行でわかる要約**
> 1. 見本の店の注文 29 件を状態ごとに数え、出荷が済んでいない注文の止まり方を調べたデータ分析です。
> 2. 済んでいない 18 件のうち 11 件は担当が決まっておらず、出荷可のうち 2 件は、出荷期限を過ぎていました（確信度は高）。
> 3. 次の一手は、出荷期限が過ぎた 2 件を先に出し、担当の無い 11 件を割り当てることです。

| 項目 | 内容 |
|---|---|
| 読み手と決めること | 出荷の当番が、11-06 の朝にどの注文から手を付けるかを決めるために読む |
| 集計した人 / 確かめた人 | 取りまとめ役 / 7 章の命令を別の端末で回し直した依頼者 |
| 状態 | 確定（完成例。データは見本アプリの架空の注文） |
| 様式 | 見本アプリに既存の分析は無いので、`skills/documents/templates/analysis.md` の雛形を使った |
| 版 | 1.0（2026-11-27） |

## 1. 問いと答えで決まること

問いは 1 つで、出荷が済んでいない注文がどの状態に何件あり、どこで手が止まっているかです。答えを見て、朝の当番は最初に出す注文を決めます。

| 番号 | 問い | 答えで決まること |
|---|---|---|
| 1 | 出荷が済んでいない注文は、どの状態に何件あり、担当と期限はどうなっているか | 当番が割り当てる注文と、その順 |

## 2. データの出どころと条件

出どころは見本アプリの注文データ `samples/api/seed-orders.json` で、時点はファイルの `scene` にある 2026-11-06 09:52 です。1 時点の写しなので、期間の推移は見ていません。

| 項目 | 内容 |
|---|---|
| 出どころ | `samples/api/seed-orders.json` の `orders`（見本の店の注文） |
| 期間か時点 | 2026-11-06 09:52 の 1 時点。注文の日時は 11-03 13:22 から 11-06 09:47 まで |
| 件数 | 29 件 |
| 条件 | 全件。状態（`status`）で分け、担当（`staff`）が空の注文と、出荷期限（`shipDue`）が 11-05 以前の注文を数えた |
| 除いた行 | 別の店の注文（`otherShopOrders`、1 件）と過去の注文（`pastOrders`、2 件）。見本の店の今日の出荷に関わらないため |

## 3. 集計

状態ごとに、件数と金額、担当の無い件数、出荷期限が過ぎた件数を数えました。状態の名前は、見本アプリの画面の表示に合わせています。

| 状態（`status`） | 件数 | 金額（円） | 担当なし | 期限を過ぎた |
|---|---|---|---|---|
| 出荷可（ready） | 12 | 125,770 | 6 | 2 |
| 要対応（action） | 3 | 26,728 | 2 | 0 |
| 決済待ち（pending） | 3 | 19,603 | 3 | 0 |
| 済（shipped） | 11 | 57,590 | 0 | 0 |
| 合計 | 29 | 229,691 | 11 | 2 |

## 4. 解釈

出荷が済んでいない注文は、済以外の 3 行を足した 18 件で、金額は 172,101 円です。担当が無いのはその 6 割を超える 11 件で、手が止まっている主な所は割り当ての前だと読めます。出荷可の 12 件は、すぐ出せる状態なのに半分の 6 件が担当なしでした。期限を過ぎた 2 件もこの出荷可の中にあり、どちらも担当は付いています。

要対応の 3 件の内訳は、住所の不備 2 件と決済の失敗 1 件です（`alert` の値）。決済待ちの 3 件は、全部がコンビニ払いの入金待ちでした。全件を数えたので、数字の確信度は高です。ただ、見本の架空のデータなので、実在の店の傾向とは読めません。

## 5. 未確認と限界

数えていないのは、時間の推移と、担当ごとの手の空き具合です。どちらも、割り当ての順を変えるかもしれません。

| 未確認 | 理由 | 答えへの影響 |
|---|---|---|
| 担当なしの件数の推移 | データが 1 時点の写しで、前日の値が無い | 割り当ての遅れが今朝だけか、毎朝かは分からない |
| 担当ごとの残りの件数と作業時間 | 作業時間の記録がデータに無い | 割り当て先の偏りは決められない。当番の判断に任せる |
| 期限を過ぎた 2 件の遅れの理由 | 理由の欄がデータに無い | 2 件を先に出す順は変わらない |

## 6. 次の一手

まず、出荷期限が過ぎた 2 件を出し、その後に担当の無い 11 件を割り当てます。要対応の 3 件は、割り当てと別に、住所と決済の確認へ回します。

| 次の一手 | 担当 | 期限 |
|---|---|---|
| 期限を過ぎた出荷可の 2 件（581950、582757）を出荷する | 出荷の当番 | 2026-11-06 12:00 |
| 担当の無い 11 件を、当番の誰かに割り当てる | 出荷の当番 | 2026-11-06 12:00 |
| 要対応の 3 件の住所と決済を、注文した人に確かめる | 問い合わせの担当 | 2026-11-06 17:00 |

## 7. 再現の命令

My-Lab の直下で次の命令を回すと、3 章の表と同じ数字が出ます。ファイルを読むだけで、データは書き換えません。

```sh
python3 -I -c '
import json, collections
o = json.load(open("samples/api/seed-orders.json"))["orders"]
c = collections.defaultdict(lambda: [0, 0, 0, 0])
for x in o:
    r = c[x["status"]]
    r[0] += 1; r[1] += x["amount"]; r[2] += x["staff"] is None; r[3] += x["shipDue"] < "2026-11-06"
for k, v in sorted(c.items()): print(k, *v)
print("total", *[sum(v[i] for v in c.values()) for i in range(4)])
'
```

出力は状態ごとに、件数・金額・担当なし・期限を過ぎた、の順です。2026-11-27 に回した結果は、次のとおりでした。

```text
action 3 26728 2 0
pending 3 19603 3 0
ready 12 125770 6 2
shipped 11 57590 0 0
total 29 229691 11 2
```
