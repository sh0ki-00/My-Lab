# 注文一覧で期間を 1 年にすると、表示に 9 秒かかる

> **3 行でわかる要約**
> 1. 管理画面の注文一覧で、期間を 1 年にすると表示に 9 秒かかる不具合の Issue です。
> 2. 期間を 1 年にしても、3 秒以内に最初の 50 件が出れば完了です。
> 3. 着手する人は、まず「起きていること」の手順で再現し、手がかりの表のログから読んでください。

この Issue の件数、時間、人数はすべて架空です。

## 背景と目的

CS（お客さまの問い合わせ窓口）の担当者 4 人は、返品の電話を受けると、注文一覧で客の注文を探します。注文番号が分からない客が多いため、期間を 1 年にして氏名で探すことが、1 日に約 60 回あります。そのたびに 9 秒待たされ、電話の相手も待たせています。
目的は、電話を保留にせずに注文を見つけられるようにすることです。年末は注文が 2.5 倍に増え、待ち時間も延びるので、12 月の前に直します。

| 項目 | 今の値 | 出どころ |
|---|---|---|
| 期間 1 年の表示時間 | 平均 9.2 秒（最大 14 秒） | 管理画面のアクセスログ（10 月） |
| 期間 1 か月の表示時間 | 平均 1.1 秒 | 同上 |
| 期間 1 年で探す回数 | 1 日に約 60 回 | CS の作業記録（10 月） |

## 起きていること

再現は毎回できます。検証環境でも本番でも、同じように遅くなります。

1. 管理画面に、CS 担当者の権限でログインします。
2. 「注文一覧」を開きます。
3. 「期間」で「過去 1 年」を選びます。
4. 「検索」を押します。

| 項目 | 内容 |
|---|---|
| 期待する結果 | 3 秒以内に、最初の 50 件が出る |
| 実際の結果 | 9 秒前後、読み込み中の表示のまま待たされ、そのあと 50 件が出る |
| 再現の頻度 | 毎回（10 回中 10 回） |
| 環境 | 本番と検証環境。Chrome 131、macOS 15。端末と回線を変えても同じ |

原因の見当は付いていますが、まだ確かめていません。見当は、事実と分けて「手がかり」の表に書きました。

## 完了の条件

完了の条件は 4 件です。どれも、確認方法のとおりに確かめれば判定できます。

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | 期間 1 年で、最初の 50 件が 3 秒以内に出る | 検証環境で手順 1〜4 を 10 回行い、10 回とも 3 秒以内 |
| 2 | 期間 1 か月の表示が、今より遅くならない（1.1 秒以内） | 同じく 10 回測る |
| 3 | 2 ページ目以降も、3 秒以内に出る | 期間 1 年の結果で、2〜5 ページ目を開いて測る |
| 4 | 表示する注文の中身と並び順が、直す前と同じ | 直す前と後で、同じ条件の 50 件を突き合わせる |

## やらないこと

この Issue では、表示の遅さだけを直します。範囲の外は次のとおりです。

| やらないこと | 理由 |
|---|---|
| 絞り込みの条件を増やす | 別の要望なので、別の Issue にする |
| 注文一覧の画面の見た目を変える | 遅さとは関係がない |
| CSV の書き出しを速くする | 別の画面で、原因も違う |

## 手がかり

着手する人が最初に見る場所です。見当はまだ確かめていないので、事実と分けて書きました。

| 種類 | 場所 | 分かっていること |
|---|---|---|
| ログ（事実） | 管理画面のアクセスログ、`GET /admin/orders` | 期間 1 年で 9 秒前後。期間が長いほど遅い |
| コード（事実） | 注文一覧の API で、一覧を取る処理 | 期間で絞ったあと、全件を読んでから 50 件に切っている |
| 見当（未確認） | 同上 | 全件を読む作りと、受注日時の列に索引が無いことが原因に見える |
| 過去の決定 | 決定記録「注文一覧の作り直し」 | 画面に出す分だけ読む作りに変える方針は、承認済み |

## 用語

この Issue で初めて出る言葉を、言い換えて並べます。

| 用語 | 意味 |
|---|---|
| API | 画面と注文の記録をつなぐ窓口。画面はここに「注文を 50 件ください」と頼む |
| 索引 | 記録を速く探すための目次。本の索引と同じ働き |
| 検証環境 | 本番と同じ作りの、試すための環境。本物の客は使わない |
