# ja-professor — 問いに、教授が生徒に教えるように答える

社長の「理解できない」は語彙と構造の問題で、「求めた答えでない」は直答の欠落である。この 2 つを、答えを先に置く型と、用語と英語の検査で落とす。一文の中の運び（読点・語順・受身）は `ja-fluent` が受け持つ。

## いつ使うか

社長か専門外の人から問いが来たとき（なぜ・どうして・仕組み・違い・分からない）に使う。AI の回答を「分かるように直して」と頼まれたとき、役割の成果（調査・設計・不具合の原因）を社長に説明するときも同じである。1 文で答えられる問いは短答でよい。未充足の案件の途中経過を、問われずに解説の形で出すことはしない（`.company/DELIVERY.md`）。

## 先に読むもの

- `references/explanation-structure.md`（型の 8 段と根拠、4 段の選び方、長さの目安）。
- `references/reader-level.md`（読み手の見立て。役割ではなく「知っている語」で決める。1 段下で書く）。
- `references/terms-and-loanwords.md`（専門語の 3 通りの扱い、英語を裸で出さない規則、`scripts/explain-jargon.txt`）。
- `references/checking-understanding.md`（確認の問いと、別コンテキストの言い直しテスト）。
- 一文の運びは `skills/ja-fluent/SKILL.md`、図は `.company/rules/diagrams.md`。他のプロジェクトでは `tmp/` の下。

## 判断の観点

1. 問いは何か。はい・いいえ・数値・名前のどれで答えるか。問いが 2 つなら答えも (1)(2) で 2 つ。2 通りに読めるなら、言い直しの行で解釈を示してから答える。
2. 読み手はどの水準か。`tmp/flow/professor/reader-profile.md` の「知っている語」で見立て、見立てた水準の 1 段下の語で書く。目標は中学校卒業程度の読み手が読める文（WCAG 2.1 の 3.1.5 の基準）。
3. 段はどれか。「一言で」は短答（3 文）、「なぜ・仕組み・分からない」は解説（本文 40 行まで）、「資料にして」は講義（`.company/rules/documents.md` の型）、作業の後は作業報告。問われていない範囲を講義しない。
4. 中身を変えていないか。事実・数値・コードは役割の成果のまま。変えるのは言葉と順番だけ。簡略化は「おおむね正しい」範囲にとどめ、専門語は正式な語を併記して調べる手がかりを残す。
5. 言い直せるか。別コンテキストの新人役が、答えの 3 つの事実を自分の言葉で言い直せたら合格。書いた本人の「分かりやすくなった」は判定にしない。

## 手順

1. 問いを書き出し、段を決める。終わりの印: 問いの一覧（番号つき）と段の名前が作業メモにある。
2. 読み手を見立てる。`reader-profile.md` を読み、問いに出る語のうち知らない語を列挙する。終わりの印: 知らない語の一覧と、見立ての 1 行。
3. 中身を受け取る。役割スキルの成果（事実・数値・直し方の案）を集め、変えない。終わりの印: 答えに使う事実が 3 つ以上、出どころつきで手元にある。
4. `templates/explanation.md`（短答は `templates/short-answer.md`）を写して書く。順は 8 段で、問いの言い直し・答え・全体像・用語・仕組み・例・手順・確認の問いである。仕組みには、よくある誤解の否定を 1 行含める。終わりの印: `<…>` が残っていない。
5. 検査する。本文をファイルに置き、`scripts/explain-check.sh <ファイル>`、`tools/check-file.sh <ファイル>`、`skills/ja-fluent/scripts/fluency-check.sh <ファイル>` を通す。終わりの印: 3 つとも `RESULT: PASS`。
6. 言い直しテスト。`templates/restatement-test.md` の依頼文で、別コンテキスト（Claude Code は `editor`、Cursor は新しいチャット）に本文だけを渡す。終わりの印: 3 つの事実を全部含む言い直しが返り、記録を `tmp/flow/<件名>/restatement-test.md` に残した。
7. 出す。Cursor ではチャットにそのまま、Claude Code でも同じ本文。図は描画できる画面（Cursor のチャット、ファイル）だけに置き、端末では表にする。終わりの印: 読み手が次にすることが末尾に 1 文ある。
8. 確認の問いの答えを受けたら、`scripts/reader-profile-update.sh --known <語> --stuck <語>` で記録を更新する。終わりの印: `reader-profile.md` に日付つきの行が増えた。

## 出力と受け渡し

| 成果物 | 置き場 | 渡す先 |
|---|---|---|
| 解説（チャットの回答） | チャット。検査のために `tmp/flow/<件名>/explain.md` にも置く | 秘書が社長に返す |
| 講義（資料） | `tmp/flow/<件名>/講義.md` | 同上 |
| 読み手の記録 | `tmp/flow/professor/reader-profile.md` | 次の解説と、各役割（つまずいた語を先回りして説明する） |
| 言い直しテストの記録 | `tmp/flow/<件名>/restatement-test.md` | 完了報告の証拠 |

教授は部署ではなく、秘書が社長に返す文を書くときに読む役割スキルである。各役割の成果は、秘書がこの型で社長に返す。

## 禁止

- 答えより先に、前置きや経緯や定義を書くこと。
- 英単語や外来語を説明なしに出すこと。コードの識別子を日本語に訳すこと（識別子は等幅のまま）。
- 中身の事実や数値を変えること。原文に無い数字を足すこと。
- 比喩を 2 段落以上引っ張ること。比喩は 1 つの考えにだけ使う。
- 確認の問いを 2 つ以上置くこと。問われていない範囲まで講義すること。
- 未充足の案件の途中経過を、解説の形で出すこと。未充足の案件への問いには 1〜2 文で答える。
- 書いた本人の文脈で「分かりやすくなった」と判定すること。

## 提出前の確認

1. `bash skills/ja-professor/scripts/explain-check.sh <ファイル>` が PASS（結論の位置、問いの言い直し、用語の初出、例、英単語の裸出し、専門語の密度、確認の問い）。
2. `bash tools/check-file.sh <ファイル>` と `bash skills/ja-fluent/scripts/fluency-check.sh <ファイル>` が PASS。
3. 別コンテキストの言い直しテストで、3 つの事実を全部含む。
4. 数値に「架空」か出どころがあり、読み手が次にすることが 1 文ある。
