# 確認の問いと、言い直しテスト

> **3 行でわかる要約**
> 1. 解説の最後に確認の問いを 1 つ置き、別コンテキストの新人役に言い直させる決まりです。言い直しに 3 つの事実が入れば、理解できる解説と判定します。
> 2. 根拠は、Bloom の個別指導の研究と、Freeman ほかの確認の問いの研究です。Feynman の「新入生に説明できなければ理解していない」も土台にしました。
> 3. 判定は書いた本人がせず、`templates/restatement-test.md` の依頼文で別コンテキストに頼みます。

## 1. 確認の問い

解説の最後に、問いを 1 つだけ置きます。2 つ以上は読み手の負担になり、答えが返りません。

| 問いの型 | 文 | いつ |
|---|---|---|
| 最も曖昧な点 | この説明で一番分かりにくかった所はどこでしょうか | 既定。次の解説はそこから始める |
| 自分の言葉で | この仕組みを一言で言うと、どうなりますか | 読み手が「分かった」と言ったとき |
| 判断の確認 | 案 A で進めてよいでしょうか | 手順の段で承認が要るとき（確認の問いとは別に 1 文で） |

答えが返ったら、`scripts/reader-profile-update.sh` で「知っている語」と「つまずいた語」を記録します。答えが無いときは記録を変えず、次の解説で同じ語をもう一度括弧で説明します。

## 2. 言い直しテスト

理解できる解説かは、書いた本人には判定できません。別コンテキスト（Claude Code は `editor`、Cursor は新しいチャット）に本文だけを渡し、3 文で言い直させます。

1. 答えの段から、言い直しに含まれるべき事実を 3 つ抜きます。例は「1 件ずつ取るから 1 + N 回」「ID の一覧でまとめて 3 回」「件数が増えても回数は同じ」の 3 つです。
2. `templates/restatement-test.md` の依頼文に本文を貼り、別コンテキストに渡す。
3. 返ってきた言い直しに、3 つの事実が番号で全部含まれていれば合格。1 つでも欠ければ、その段を直して出し直す。
4. 記録を `tmp/flow/<件名>/restatement-test.md` に残す（依頼文、言い直し、番号、合否）。
