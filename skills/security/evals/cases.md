# security の試験ケース

`run.sh` が回す試験ケースは 7 件です。どれも機械で合否が決まり、1 件でも落ちたら提出しません。

| # | ケース | 与えるもの | 合格の条件 |
|---|---|---|---|
| 1 | 完成例と雛形 | 注文一覧の RoE・報告・検知の行列の完成例と、その雛形 | 完成例は roe-check・report-check（`--roe` で RoE と突き合わせても）・cvss4 --report・--matrix を通り、雛形は穴埋めのままなので落ちる |
| 2 | RoE の欠け | `fixtures/bad-roe.md` | 所有の確認・範囲外の宛先・許可・連絡先・期間・止める条件・やらないことの 7 つで落ちる |
| 3 | 報告の 5 点の欠け | `fixtures/bad-report.md` | 何ができてしまうか・直し方・再検証・重さと採点の根拠・採点の根拠・範囲外の宛先・攻撃コードの 7 つで落ちる |
| 4 | 点数の食い違い | `fixtures/wrong-score-report.md` と、完成例の 3 つの文字列 | 盛った点数と軽く書いた重さで落ち、完成例の 9.3・7.1・5.3 は計算と同じ |
| 5 | 検知の行列の欠け | `fixtures/bad-matrix.md` | 段階の数・通知・検知・検証の 4 つで落ちる |
| 6 | 再検証の命令 | 報告が指す見本の試験 3 本 | `samples/api/test_orders_api.py` の 3 本が、網を使わずに全部通る |
| 7 | 再検証の宛先と試験の置き場 | `fixtures/bad-copy-report.md` と `fixtures/bad-copy-roe.md` | `--roe` なしでは通り、`--roe` では RoE の範囲外・再検証の写し・試験の置き場・立てる写しの 4 つで落ちる |

検査の自己試験（`--selftest`）は、ケースとは別に `scripts/` の .sh ごとに回します。再検証の HTTP の要求は、手元の写しを立てる必要があるので、ここでは回さず報告の手順で回します。
