# 攻撃の基準表: 入口ごとに当てる手口と、道具が守る 9 つの線

> **3 行でわかる要約**
> 1. ローカルで起こしたアプリに送る手口を、12 と、送らない検査 1 つに決めた表です。
> 2. 手口は OWASP API Security Top 10（2023 年版）の項目に結び、結果は「守れた」「脆弱性」「対象外」で埋めます。
> 3. 道具（`scripts/attack_run.py`）は、この表にある手口だけを送り、9 つの線を自分で守ります。

攻撃の相手は、バックエンドとフロントエンドのソースコードから手元で起こしたアプリだけです。クラウドの環境・本番・第三者には、1 本も送りません。インフラ（AWS の設定など）は見ません。設計の段階のインフラは、インフラの役割が受け持ちます。

## 1. 手口の表

手口は A01〜A12 です。当てる入口は、プロジェクトの地図（キャッチアップ）か、`probe.json`（入口の一覧）から決めます。「守れたとみなす応答」の列が、脆弱性かどうかの分かれ目です。

| ID | 手口 | 当てる入口 | 守れたとみなす応答 | OWASP API 2023 |
|---|---|---|---|---|
| A01 | 認証なしで入る | 認証が要る入口 | 401 か、ログインへの移動 | API2 |
| A02 | 他人の物を読む・書く | 持ち主で分ける ID の入口 | 404 で、あることを教えない | API1 |
| A03 | 権限を越える | 書き込みと管理の入口 | 403 で、データが変わらない | API5 |
| A04 | 余計な項目を読む・書く | 書き込みと、人の情報を返す入口 | 足した項目が無視され、鍵やハッシュが出ない | API3 |
| A05 | 鍵とセッションを破る | ログインと、鍵を使う入口 | 推せる鍵と期限切れの鍵が 401 | API2 |
| A06 | 入力でクエリや命令を壊す | 入力を受け取る入口 | 400 か無反応。誤りの本文に内部の値が無い | API8 |
| A07 | 画面にスクリプトを差し込む | 入力が画面に出る入口 | 文字として出て、動かない | 画面側 |
| A08 | 他のサイトから操作させる | 状態を変える入口 | 別の出どころ（Origin）を断る | 画面側 |
| A09 | 量と連打 | ログイン、一覧、受け取り | 途中から断り、上限で切る | API4 |
| A10 | 外へつながせる | URL を受け取る入口 | 手元の見張り役に何も届かない | API7 |
| A11 | ファイルの受け取りと配信 | ファイルの入口 | 断り、決めた置き場の外に書かない | 入力の検証 |
| A12 | 設定と漏れ | 全体と、配る物 | 内部の値が出ない。待ち受けは 127.0.0.1 だけ | API8・API9 |
| S01 | 依存と秘密（送らない検査） | リポジトリの中身 | 重大な脆弱性が 0 件、秘密が 0 件 | 全体の検証の 11 番 |

在庫の買い占めのような機能ごとの悪用は、この表では拾えません。危ない機能の計画には「悪用のシナリオ」を 3 つ書き、表に足します。

## 2. 道具が守る 9 つの線

道具は、宛先と量の線を 9 つ、自分で守ります。線の多くは、常設の RoE（交戦規則。攻撃してよい範囲と条件を決めた文書）の中身を読んで確かめます。今の判定の本体（`hooks/guard-core.sh`）は宛先を見ないので、線を守る場所は道具の中に置きます。1 つでも外れたら、1 本も送らずに止まります。

| # | 線 | 中身 |
|---|---|---|
| 1 | 許可が先 | 常設の RoE が有効で、今が期間の中で、範囲の指紋（中身から計算する短い値）が合う |
| 2 | 宛先は手元だけ | 127.0.0.1・localhost・::1 だけ。名前を引かず、数字の宛先 127.0.0.1 で送る |
| 3 | 追わない、通さない | 移動（リダイレクト）を追わない。代理（プロキシ）を通さない |
| 4 | 待ち受けを見る | そのポートで待つプロセスが、RoE の起動の命令で立った物か（lsof か ss で見る） |
| 5 | 下流を見る | RoE の下流の表が、手元・作り物・使い捨てだけか。外の宛先があれば止まる |
| 6 | 量を縛る | 手口ごと・全体の本数、同時 1 本、1 本と全体の打ち切りを RoE から読む |
| 7 | 残す物を絞る | 台帳に残すのは、手口・入口・利用者・状態番号・長さ・印の有無・時間だけ |
| 8 | 表だけ | 送るのは A01〜A12 だけ。その場で書いたプログラムは回さない |
| 9 | ポートを取り合わない | 外へつながせる試験の見張り役は、空いているポート（127.0.0.1:0）に立てる |

## 3. 道具と検査

道具と検査は、次の表のとおりです。攻撃の台帳は tmp の下に置き、PR 文や Issue 文には貼りません。

| 名前 | 役目 |
|---|---|
| `scripts/attack-run.sh` | 常設の RoE の範囲で、表の手口を送る。完了報告の「攻撃の結果」の節を書く |
| `scripts/attack-check.sh` | 攻撃の台帳の検査。線 7（秘密を残さない）を機械で確かめる |
| `templates/standing-roe.md` | 常設の RoE の雛形。機械の節（```json）が、範囲・下流・上限・期間・指紋を持つ |
| `evals/vulnerable-app/` | 脆弱性を 12 件仕込んだ、試験の的。`--fixed` でふさぐ。本番にも、ふつうの見本にも使わない |
| `evals/vulnerable-app/detect-test.py` | 検知力の試験。穴のある版で 12 件、ふさいだ版で 0 件を確かめる |

## 4. 「どこからも侵入されない」の確かめ方

5 つの数がそろったときに、「ソースコードの側は、表の範囲で確かめた」と書きます。1 つでも欠けたら、完了報告の先頭にその欠けを書きます。インフラの層は対象の外なので、「どこからも侵入されない」とは書きません。

| # | 数 | そろった状態 |
|---|---|---|
| 1 | 入口の漏れ | 0 件。一覧に無い入口が見つからない |
| 2 | 未実施 | 0 件。当てはまる手口を、全部の入口に送った |
| 3 | 脆弱性 | 0 件。前からある脆弱性が残るあいだは、そろったと書かない |
| 4 | 依存と秘密 | 重大な脆弱性が 0 件、秘密が 0 件 |
| 5 | 検出力 | サンプルに仕込んだ脆弱性を、全部見つける |
