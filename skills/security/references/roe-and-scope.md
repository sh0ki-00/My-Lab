# RoE と範囲の決め方

> **3 行でわかる要約**
> 1. 侵入テストを始める前に結ぶ RoE（交戦規則）の 6 項目と、許可の線の引き方をまとめた資料です。
> 2. 道具を向けてよいのは、社長が所有し、署名で許した検証環境と自社のコードだけです。
> 3. RoE を書くときと、試験の途中で範囲に迷ったときに開いてください。

## 6 つの項目

この節は、RoE に必ず書く 6 項目と、`roe-check.sh` が落とす欠けです。6 つのどれかが欠けたら、試験を始めません。

| 項目 | 書くこと | roe-check が落とすもの |
|---|---|---|
| 範囲 | 対象・宛先・写しの置き場・所有の確認・試してよいこと | 表が無い、所有の確認が空、所有の確認の無い外の宛先 |
| 許可 | 署名した人と日付、許可の中身 | 署名か日付が無い |
| 連絡先 | 実施する人と、止める判断をする人の役と手段 | 2 人に満たない |
| 期間 | 始まりと終わりの日付 | 日付が 2 つ無い、終わりが始まりより前 |
| 止める条件 | 当たったらすぐ止める出来事 | 2 つに満たない |
| やらないこと | 署名があってもしない操作 | 3 つに満たない、本番と第三者が無い |

写しの置き場は、宛先ごとに立てる写しのディレクトリです。報告の再現と再検証はこの宛先と置き場に合わせ、`report-check.sh --roe` が突き合わせます。直す前と直したあとで宛先を分けるときも、置き場は同じ写しにします。

連絡先には、本物の電話番号やアドレスを書きません。役と手段（取りまとめ役を通す、作業場の受付票）だけを置き、人の連絡先は依頼者が持ちます。

## 許可の線

この節は、どこまでが許された対象かの見分け方です。線の外に一度でも要求を送ったら、それ自体が止める条件に当たります。

| 対象 | 扱い | 理由 |
|---|---|---|
| 手元に写した見本（127.0.0.1） | 署名があれば試してよい | 持ち主のリポジトリの写しで、外の網に出ない |
| 自社のコード（読む・手元の試験） | 署名があれば試してよい | 網を使わず、誰の資源にも触れない |
| 自社の検証環境（手元の外） | 所有の確認を範囲の表に書き、署名をもらい直す | 宛先の持ち主を証拠で示せたときだけ |
| 本番の環境、本物の AWS のアカウント | 試さない | 破壊と停止の危険があり、役割の決まりが禁じる |
| 第三者の資産（他人のサーバー、外の網、外の部品の配布元） | 試さない | 許可が無く、法に触れる |

部品の穴は、配布元に要求を送って調べません。手元の部品の一覧と、インフラの `deps-diff.sh` の結果で見ます。

## 止める条件の選び方

この節は、止める条件に何を書くかです。条件は、起きたら試験を続けても得る物より失う物が大きい出来事にします。

- 範囲の表に無い宛先へ、要求が 1 本でも出た。
- データが、試験の想定と違う形で書き換わった。
- 鍵や個人の情報が、決めた置き場の外に出た。
- 期間を過ぎた。

止めたら、何を送ったか・何が返ったか・何を止めたかを取りまとめ役へ知らせます。再開には、RoE の直しと署名のもらい直しが要ります。

## 世界の基準

この節は、RoE と範囲の決め方の根拠です。どちらも、試験の前に範囲と許可と連絡先を文書で結ぶことを求めています。

| 基準 | 何を言っているか | 出典 |
|---|---|---|
| NIST SP 800-115 | 試験の前に、範囲・時間・連絡先・扱いを決めた計画と許可を得る | https://csrc.nist.gov/pubs/sp/800/115/final |
| PTES の事前の取り決め | 範囲・期間・止める連絡・やらないことを先に結ぶ | http://www.pentest-standard.org/index.php/Pre-engagement |
| OWASP Web Security Testing Guide | 試験の前提として、許可と範囲を確かめる | https://owasp.org/www-project-web-security-testing-guide/ |
