# 攻撃の段階ごとの検知の行列

> **3 行でわかる要約**
> 1. 攻撃の段階ごとに、ログ・検知・通知・検証の 4 つを並べる行列の作り方をまとめた資料です。
> 2. 左の列から順に埋め、ログに手掛かりが無い段階は盲点として SRE とバックエンドへ渡します。
> 3. 検知の行列を書くとき、`report-check.sh --matrix` に落とされたときに開いてください。

## 4 つの列

この節は、行列の列の意味です。どの列も、右の列は左の列が埋まって初めて作れます。

| 列 | 書くこと | 落とすもの |
|---|---|---|
| ログ | その段階で残る記録の項目（状態番号、誤りのコード、利用者、行数） | 空 |
| 検知 | 何を、何本・何分で数えるか（閾値と、架空か実測か） | 空 |
| 通知 | 誰へ、何で、すぐか集めてか | 空 |
| 検証 | 合否の分かる命令（`grep -c …` が送った本数と同じ、など） | 空、命令が無い |

行は 4 段階以上にします。入口だけを見る行列は、入られたあとの横の移動と持ち出しを見落とすからです。

## 段階の分け方

この節は、段階の切り方です。MITRE ATT&CK（攻撃者の手を段階ごとに並べた世界の一覧）の戦術から、対象で起きうるものを選びます。

| 段階 | ATT&CK の戦術 | 注文一覧の API での手 |
|---|---|---|
| 偵察 | Reconnaissance | 鍵なしで経路を探る |
| 入口 | Initial Access | 作った鍵、盗んだ鍵 |
| 権限の昇格 | Privilege Escalation | 閲覧者が書き込む |
| 横の移動 | Lateral Movement | 番号を変えて他の店を読む |
| 持ち出し | Exfiltration | 一覧を送りながら全部読む |
| 書き換え | Impact | 出荷と取り消しを大量に出す |

出典: MITRE ATT&CK の戦術の一覧（https://attack.mitre.org/tactics/enterprise/）。

## 盲点の扱い

この節は、埋まらない升の扱いです。空の升は「無い」と書いて終わりにせず、盲点の表に移して渡す先を決めます。

1. ログに手掛かりが無い升は、ログの項目を足す役（バックエンドかインフラ）へ渡す。
2. 規則が無い升は、SRE へ検知すべき経路として渡す。
3. 規則ができたら、検証の命令を回し、通知が 1 通届くことまでを確かめる。

検証の命令は、報告の再現と同じく、手元の写しと 127.0.0.1 だけに向けます。閾値は普段の操作の実測で決め、測るまでは架空と書きます。
