# CVSS 4.0 の採点

> **3 行でわかる要約**
> 1. 発見の重さを CVSS 4.0（穴の重さを 0.0〜10.0 で測る世界の決まり）の基本の値で採る手順の資料です。
> 2. 点数は手で計算せず、`cvss4.sh` に文字列を渡して出し、報告との食い違いは `--report` で落とします。
> 3. 採点に迷ったとき、計算の表を確かめるときに開いてください。

## 基本の 11 個の値

この節は、報告で採る 11 個の値と、選び方の問いです。脅威と環境の値は点数に入れず、必要なら本文で別に書きます。

| 値 | 問い | 選べる値 |
|---|---|---|
| AV | どこから届くか | N 網、A 隣の網、L 手元、P 物理 |
| AC | 攻撃者が制御できない条件が要るか | L 要らない、H 要る |
| AT | 前もって整う条件（競合や設定）が要るか | N 要らない、P 要る |
| PR | 攻撃の前に持つ権限 | N なし、L 普通の利用者、H 管理者 |
| UI | 相手の操作が要るか | N 要らない、P 受け身で要る、A 進んで要る |
| VC・VI・VA | 対象の仕組みの、読める・変えられる・止められる | H 全部か重い、L 一部、N なし |
| SC・SI・SA | 対象の外の仕組みへの、読める・変えられる・止められる | H、L、N |

迷ったら、攻撃者に有利な側を選びません。根拠の表に、選んだ理由を 1 行ずつ書き、読み手が同じ値を選べるようにします。

## 計算の手順

この節は、`cvss4.sh` が中でしている計算です。仕様書の 8 章の手順で、手で追えるように 3 段で書きます。

1. 11 個の値を、6 つの同値の群（EQ1〜EQ6）に分け、群の組を 6 桁の鍵にする。基本だけなら、脅威は A、環境の要求は H として数える。
2. 鍵で表を引き、その組の点数を得る。表は 270 行ある。
3. 同じ組の中で最も重い値からの距離を測り、1 つ下の組の点数との差に掛けて引く。小数 1 桁に丸める。

重さの区切りは仕様書の 5 章の表に従います。Critical は 9.0 以上、High は 7.0〜8.9、Medium は 4.0〜6.9 です。Low は 0.1〜3.9 で、0.0 は None と呼びます。

## 表の出典と照合

この節は、`cvss4.py` の表をどこから写したかです。表は 3 つあり、どれも FIRST（CVSS を定める団体）の公式の物です。

| 表 | 中身 | 出典 |
|---|---|---|
| LOOKUP | 270 の組の点数 | 公式の計算機の cvss_lookup.js（https://github.com/FIRSTdotorg/cvss-v4-calculator） |
| MAX_COMPOSED | 群ごとの最も重い値 | 同じ計算機の max_composed.js |
| MAX_SEVERITY | 群ごとの最大の距離 | 同じ計算機の max_severity.js |
| 重さの区切り | 点数と重さの対応 | 仕様書の 5 章（https://www.first.org/cvss/v4.0/specification-document） |

`--selftest` は、表が 270 行あることと、よく使われる 7 つの文字列の点数を確かめます。網に出られない作業場では、公式の計算機と並べた照合はできません。表を写し直したときは、公式の計算機（https://www.first.org/cvss/calculator/4.0）で同じ文字列の点数を比べます。
