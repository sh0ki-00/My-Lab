# 発見の 5 点と再検証

> **3 行でわかる要約**
> 1. 侵入テストで、発見 1 件ごとに書く 5 点と、再現と再検証の命令の書き方をまとめた資料です。
> 2. 守る側が文書だけを読んで、直しと再検証を同じ手順でやり直せる形にします。
> 3. 発見を書くとき、`report-check.sh` に落とされたときに開いてください。

## 発見の 5 点

この節は、発見 1 件に要る 5 点です。どれか 1 つでも欠けた発見は、守る側が動けないので出しません。

| 点 | 書くこと | report-check が落とすもの |
|---|---|---|
| 何ができてしまうか | 攻撃者が何を読めて何を変えられるか。証拠（応答かログの抜粋、試験の名） | 節が無い、空、証拠の語が無い |
| 再現の手順 | 穴のある版に、要求を 1 本ずつ送る命令 | 命令の囲みが無い、手元の外の宛先、攻撃のコード |
| 直し方 | どこを、どう直すか、直す役 | 節が無い、空か穴埋めのまま |
| 再検証 | 直した版に同じ手で送る命令と、合否の分かる期待の値 | 命令の囲みが無い、「期待: `404`」の形が無い。`--roe` で、RoE の範囲外の宛先、再現と別の写しの宛先、写しに無い試験 |
| 重さと採点の根拠 | CVSS 4.0 の文字列・点数・重さと、11 個の値ごとの理由 | 文字列・点数・重さが無い、理由の無い値がある |

点数と重さが計算と合うかは、`cvss4.sh --report` が別に見ます。採点の手順は `cvss4-scoring.md` にあります。

## 再現と再検証の命令

この節は、命令の書き方です。読み手はバックエンドの役で、命令を写して回し、同じ結果を得られることが目標です。

1. 準備の命令（立てる、鍵を一時のファイルに取る）を、「再現の準備」の節に 1 回だけ書く。
2. 発見ごとの命令は、要求 1 本を 1 行にする。宛先は RoE（交戦規則）の範囲で、手元の 127.0.0.1 だけ。
3. 再検証には、期待の値を「期待: `403`」の形で書く。本文の誤りのコードも並べると、合否が 1 つに決まる。
4. 見本の試験があれば、試験の名を指して 1 本だけ回す命令も添える。試験のファイルと関数は、RoE の写しの置き場の中にある物だけにする。
5. 再検証の宛先は、再現と同じ写しを直して立てた、RoE の範囲の宛先にする。別の写しの宛先で合格しても、直しを確かめたことにならない。

鍵の本物は書きません。起動のたびに作る鍵は変数に取り、文書には変数の名だけを置きます。

## 攻撃のコードを書かない線

この節は、書いてよい命令と書かない命令の線です。発見の文書は直すための物で、穴を突く道具の作り方ではありません。

| 書いてよい | 書かない（report-check が落とす） |
|---|---|
| curl で要求を 1 本送る命令 | その場で書いたプログラム（`python3 -c`、`node -e`） |
| 見本の試験を 1 本回す命令 | 埋め込みの文書、隠した命令（eval、base64 の解読） |
| 状態番号と誤りのコードを見る命令 | 攻撃の道具の呼び出し、13 行以上の命令 |

直す前の穴は、関係者（社長・秘書・直す役）の外に出しません。置き場は tmp/flow/ の下で、git に入れるかは社長が決めます。

## 穴の型と直す役

この節は、注文一覧の API でよく出る穴の型です。OWASP API Security Top 10（2023 年版）の項目に結びつけ、直す役を決めます。

| 項目 | 穴の型 | 直す役 |
|---|---|---|
| API1 資源ごとの認可 | 番号を変えると他人の注文が読める | バックエンド |
| API2 認証の穴 | 推せる鍵、期限の無い鍵 | バックエンドとインフラ |
| API4 量の制限 | 上限の無い一覧、同時の要求の上限が無い | バックエンドと SRE |
| API5 操作ごとの認可 | 閲覧者が書き込める | バックエンド |
| API8 設定の穴 | 誤りの本文に内部の値、余計な見出し | バックエンドとインフラ |

出典: OWASP API Security Top 10 2023（https://owasp.org/API-Security/editions/2023/en/0x11-t10/）。
