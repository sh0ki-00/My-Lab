# security — 許された対象だけを攻撃者の目で試し、直しと再検証まで渡す

## いつ使うか

秘書の受付票で、依頼の型が「セキュリティレビュー」「侵入テスト」「脅威の見立て」のとき。バックエンドやインフラの設計に、攻撃者の目の審査を頼まれたときにも使う。直すのはバックエンド・フロントエンド・インフラ、検知の規則を作るのは SRE で、このスキルでは決めない。

## 先に読むもの

- `.company/security/CLAUDE.md`（ペルソナ）と `.company/DELIVERY.md`、`.company/rules/evidence-and-safety.md`。
- 対象の設計と実装。バックエンドの計画 `tmp/flow/<件名>/backend-plan.md`、インフラの設計、SRE の盲点。無ければ秘書に戻す。
- `references/roe-and-scope.md`（RoE の 6 項目、許可の線、止める条件）。
- `references/five-points-and-retest.md`（発見の 5 点、再現と再検証の命令、攻撃のコードを書かない線、OWASP の項目と直す役）。
- `references/cvss4-scoring.md`（基本の 11 個の値の選び方、計算の手順、表の出典）。
- `references/detection-matrix.md`（4 つの列、段階の分け方、盲点の扱い）。
- `templates/`（`roe.md`、`pentest-plan.md`、`pentest-report.md`、`detection-matrix.md`）と `examples/`（注文一覧の見本 API の 4 点）。見本の API は `samples/api/`。

## 判断の観点

1. 道具を向ける先は、社長が所有し、署名した RoE の範囲の中か。範囲の表に無い宛先は、同じ機械の上でも外。
2. RoE を先に結んだか。範囲・許可・連絡先・期間・止める条件・やらないことの 6 つを書き、社長の署名と日付を得てから始める。
3. 発見は「何ができてしまうか」を証拠で示したか。証拠は応答とログの抜粋と試験の名で、鍵と個人の情報は入れない。
4. 守る側が文書だけで直しと再検証を再現できるか。再現は命令の形、再検証は合否の分かる期待の値つき。
5. 重さは CVSS 4.0 の基本の値で採り、11 個の値ごとに理由を書いたか。点数は手で出さず `scripts/cvss4.sh` で出す。
6. 入られたあとも見えるか。攻撃の段階ごとに、ログ・検知・通知・検証がそろっているか。埋まらない升は盲点として渡す。

## 手順

1. 入力を読み、守りたい物と攻撃者の見立てを書く。終わりの印: 攻撃者ごとに持っている物と狙いを 1 行で言える。
2. RoE を `templates/roe.md` から書く。対象は手元の写しか自社の検証環境だけにし、所有の確認と、宛先ごとの写しの置き場を範囲の表に書く。終わりの印: `scripts/roe-check.sh <RoE>` が PASS。
3. 秘書を通して、社長の署名と日付をもらう。署名が無いうちは、道具を 1 つも向けない。
4. 計画を `templates/pentest-plan.md` から書く。攻撃者ごとに試すことを、要求 1 本と「穴とみなす応答」で決め、OWASP API Security Top 10 の項目に結びつける。
5. 試す。見本は RoE がその宛先に書いた写しの置き場から手元で立て、宛先は範囲の表の 127.0.0.1 だけにする。鍵は起動のたびに作られる物を一時のファイルに取り、文書に書かない。止める条件に当たったら、すぐに止めて秘書へ知らせる。
6. 穴ごとに、報告の型で 5 点を書く。再現は穴のある版、再検証は直した版に送る命令にする。再検証は、再現と同じ写しを直して立てた RoE の宛先に向け、名を挙げる試験はその写しの置き場の中の物にする。期待の値は「期待: `404`」の形で書く。
7. 採点する。11 個の値を選び、`scripts/cvss4.sh '<CVSS:4.0/…>'` で点数と重さを出し、根拠の表に値ごとの理由を書く。
8. 検知の行列を `templates/detection-matrix.md` から書く。攻撃の段階を 4 つ以上並べ、ログの列から埋める。手元で検証の命令を回し、ログの行数を書く。
9. 検査を通す。`scripts/report-check.sh --roe <RoE> <報告>`、`scripts/cvss4.sh --report <報告>`、`scripts/report-check.sh --matrix <行列>`、`tools/check-file.sh` を各文書に回す。秘書が `editor` で読み手テスト（セキュリティからは呼べない）。
10. 渡す。発見と再検証の依頼はバックエンドとフロントエンドへ、設計と権限の穴はインフラへ、検知すべき経路と盲点は SRE へ渡す。
11. 直ったと言われたら、報告の再検証の命令をそのまま回す。全部の期待の値が出たら、報告の状態と再検証の結果の表を直す。

## 出力と受け渡し

| 成果物 | 置き場 | 渡す先 |
|---|---|---|
| RoE | `tmp/flow/<件名>/roe.md` | 秘書（社長の署名をもらう） |
| 侵入テストの計画 | `tmp/flow/<件名>/pentest-plan.md` | 秘書（承認伺いに範囲・期間・止める条件を写す） |
| 侵入テストの報告 | `tmp/flow/<件名>/pentest-report.md` | バックエンド、フロントエンド（直しと再検証）、インフラ（設計と権限の穴） |
| 検知の行列 | `tmp/flow/<件名>/detection-matrix.md` | SRE（検知すべき経路と盲点）、バックエンド（ログの項目） |

秘書には、要約 10 行以内・未解決の対立・承認が要る判断の 3 つを `skills/secretary/templates/reply-from-role.md` の型で返す。承認が要るのは、RoE の署名と範囲の追加と破壊的な試験である。直す前の穴を関係者の外に知らせるときも承認が要る。

## 禁止

- 社長が所有し許可した対象（検証環境と自社のコード）のほかに道具を向けない。範囲と許可と連絡先を書いた RoE（交戦規則）が無ければ始めない。
- 本番の環境と本物の AWS の口座への要求。第三者の資産（他人のサーバー、外の網、外の部品の配布元）への到達。
- 署名と止める条件の無い破壊的な試験。負荷をかけて止める試験、データを消す試験。
- 攻撃のコードを報告に書く。その場で書いたプログラム、隠した命令、攻撃の道具の呼び出しを命令に入れる。
- 修正前の穴を、関係者（社長・秘書・直す役）の外に広げる。
- 鍵・合言葉・個人の情報を、文書とログと出力に書く。試験の鍵は試すたびに作り、終わったら消す。
- 測っていない数値を実測と書く。点数を手で計算して書く。
- 他の役割の判断を代行する。承認のない commit・push・Issue と PR の作成。

## 提出前の確認

1. `scripts/roe-check.sh <RoE>` が PASS で、社長の署名と日付がある。
2. `scripts/report-check.sh --roe <RoE> <報告>` と `scripts/cvss4.sh --report <報告>` が PASS。再現・再検証・試験は、RoE の範囲の宛先と写しの置き場に合っている。
3. `scripts/report-check.sh --matrix <行列>` が PASS。検証の命令を手元で回した結果を行列に書いた。
4. 再検証の命令を直した版で回し、全部の期待の値が出た。宛先は RoE の範囲の中だけだった。
5. 各文書の `tools/check-file.sh` と `tools/check-refs.sh` が PASS。
6. 秘書に返す 3 つ（要約・未解決の対立・承認が要る判断）が `skills/secretary/scripts/reply-check.sh` を通る。
