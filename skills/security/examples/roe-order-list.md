# RoE: 注文一覧の見本 API の侵入テスト

> **3 行でわかる要約**
> 1. 架空の EC サイトの管理画面にある注文一覧の API へ、侵入テストをする前に結ぶ RoE（交戦規則）の完成例です。
> 2. 対象は手元で立てる見本の API だけで、宛先は 127.0.0.1:18080 の 1 つに限ります。本番と第三者の資産には向けません。
> 3. 対象の持ち主の署名と日付がそろうまで、道具を 1 つも向けません。数値はすべて架空です。

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-11-08 |
| 状態 | 署名済み（見本のため、署名も架空） |
| 数値 | すべて架空 |
| 計画 | `pentest-plan-order-list.md` |
| 置き場 | tmp/flow/order-list/roe.md |

## 用語

この RoE で使う語を先に決めます。

| 用語 | 意味 |
|---|---|
| RoE | 交戦規則。どこまで試してよいかを、範囲・許可・期間・止める条件で決めた文書 |
| 写しの置き場 | 宛先で立てる API のファイルがあるディレクトリ。報告の再現・再検証・試験は、ここに合わせる |
| 鍵 | 見本の API が起動のたびに作る作り物の鍵。起動を止めると使えない |

## 範囲

試してよい対象は、下の表の 2 行だけです。表に無い宛先は、同じ機械の上でも範囲の外として扱います。

| 対象 | 宛先 | 写しの置き場 | 所有の確認 | 試してよいこと |
|---|---|---|---|---|
| 見本の注文 API | http://127.0.0.1:18080 | `samples/api/` | 持ち主のリポジトリの中の物を、手元で立てる | 認可・鍵・入力・エラーの応答を、要求 1 本ずつ確かめる |
| 見本の API のコード | 網を使わない | `samples/api/` | 持ち主のリポジトリの中の物 | 読んで穴を探す。手元の試験を回す |

宛先の機械は作業場の 1 台だけで、外の網には出ません。見本の API は注文のデータをメモリーの上にだけ持つので、立てても置き場のファイルは書き換わりません。そのため写しを作らず、置き場からそのまま立てます。

範囲を足すときは、この表を直して署名をもらい直します。報告の再現と再検証の宛先、名を挙げる試験のファイルは、この表の宛先と置き場に合わせます。

## 許可

許可は対象の持ち主の署名で決まり、口頭の了承では始めません。署名は次の 1 行です。

- 署名: 対象の持ち主（2026-11-08、見本のため架空の署名）
- 許可の中身: 上の範囲の表の 2 行に、期間の中だけ道具を向けてよい

## 連絡先

試験の途中で止める判断が要るときの連絡先です。本物の電話番号やアドレスは書かず、役と手段だけを置きます。

| 役 | 人 | 連絡の手段 | いつ連絡するか |
|---|---|---|---|
| 実施 | セキュリティ | 作業場の受付票 | 始めるとき、止めたとき、終わったとき |
| 止める判断 | 依頼者 | 取りまとめ役を通す | 止める条件に当たったとき |
| 直す側 | バックエンド | 取りまとめ役を通す | 発見を渡すときと、再検証を頼むとき |

## 期間

期間は 2026-11-08 から 2026-11-09 までの 2 日です。期間の外では、見本の API を立てたままにしません。

## 止める条件

次のどれか 1 つに当たったら、すぐに API を止めて取りまとめ役へ知らせます。

- 範囲の表に無い宛先へ、要求が 1 本でも出た。
- 見本の API のデータか置き場のファイルが、試験の想定と違う形で書き換わった。
- 鍵や個人の情報が、要約のログか出力の外に出た。
- 期間を過ぎた。

## やらないこと

次の 5 つは、署名があってもしません。

- 本番の環境と、本物の AWS のアカウントへの要求。
- 第三者の資産（他人のサーバー、外の網の宛先）へ道具を向けること。
- 負荷をかけて止める試験と、データを消す試験。
- 攻撃のコードを報告書に書くこと。
- 直す前の穴を、関係者（依頼者・取りまとめ役・バックエンド）の外に話すこと。
