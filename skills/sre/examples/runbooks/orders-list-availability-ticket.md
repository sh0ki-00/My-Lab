# Runbook: 注文一覧の可用性のチケット（OrdersListAvailabilityTicket）

> **3 行でわかる要約**
> 1. 注文一覧の API の失敗が少しずつ続き、可用性のエラーバジェットが 3 日で 10% 減る速さのときに、当番が開く手順書です。
> 2. 夜は起こさず、次の勤務の時間に直します。見本で起こせる原因は、1 人の利用者の鍵で同時の要求を積む一括の道具です。
> 3. 確かめる命令で断りの理由と利用者を数え、連打の元を止めてから、直ったことを確かめてください。

| 項目 | 内容 |
|---|---|
| 通知 | `OrdersListAvailabilityTicket`（チケット。勤務の時間に直す） |
| 条件 | 3 日と 6 時間の失敗率が、どちらも 0.1% 超え |
| SLO 定義書 | `../slo-order-list.md` |
| 対象 | 見本の API の写し。本番の命令は人が出し、AI は流さない |
| 数値 | 目標・閾値・時刻はすべて架空 |
| 訓練 | `../../scripts/runbook-drill.sh` が C5、表の外の 1 件、別の起動の 1 件を使い捨ての写しで起こし、この手順で直るかを確かめる |

## 用語

この節は、手順に出る略語と道具の名前をまとめます。2 回目からは説明を省きます。

| 用語 | 意味 |
|---|---|
| SLO | 利用者に約束する信頼性の目標。ここでは 30 日で 99.9% の要求が成功すること |
| SLI | 目標を測る数。ここでは有効な要求のうち 200 を返した割合 |
| エラーバジェット | 目標の外に出てよい失敗の量。30 日で要求の 0.1% |
| Runbook | 当番の手順書。通知 1 つに 1 本 |
| 外形の確かめ（probe） | 利用者と同じ道で一覧を呼ぶ確かめ。`sample-api.sh probe` |
| 同時の要求の上限 | 利用者 1 人あたり 8 本（架空）。超えた要求は待たずに 503 で断る |

## 準備

この節は、命令が使う変数を決めます。どの命令の前にも、次の 2 行を流してください。値の意味は可用性の呼び出しの Runbook と同じです。

```sh
: "${API_DIR:=tmp/flow/stage5/api}" "${RUN:=tmp/flow/stage5/run}" "${PORT:=8080}" "${SRC:=samples/api}" "${SRE:=skills/sre/scripts}" "${KEYS:=$RUN/keys.txt}"
export API_DIR RUN PORT SRC SRE KEYS
```

| 変数 | 既定の値 | 意味 |
|---|---|---|
| API_DIR | tmp/flow/stage5/api | 見本の API の写し |
| RUN | tmp/flow/stage5/run | 要約のログ・pid・退避した file の置き場。一括の道具の pid も `batch.pid` に置く |
| PORT | 8080 | 写しが 127.0.0.1 で待ち受けるポート |
| SRE | skills/sre/scripts | 当番の道具 |
| KEYS | $RUN/keys.txt | 作り物の鍵の file。無ければ道具が $RUN/keys.* を探す。pid の記録が無ければ、道具は PORT の待ち受けから写しの API を見つける。ほかの置き場の鍵は読まず、道具の鍵で入れなければ start が道具で立て直して作り直す |

## 症状

この節は、利用者に何が見えているかを書きます。ある運営担当者の画面にだけ、ときどき「注文一覧を読み込めませんでした」が出ます。読み込み直すと出ることが多く、ほかの担当者は困っていません。

| 見えるもの | 利用者への影響 |
|---|---|
| 一覧の要求の一部が 503 を返す（コード `ORDER_LIST_UPSTREAM_SLOW`） | 同じ鍵を使う担当者の画面が、ときどき誤りの文になる |
| 503 の要求は、待たずにすぐ返る | 画面の読み込み中は長くならない |

このまま続くと 30 日で予算を使い切ります。呼び出しには届かない速さなので、勤務の時間に直します。

## 確かめる命令

この節の命令は読むだけで、何も変えません。上から順に流し、出力をそのまま記録に貼ります。

```sh
bash "$SRE/sample-api.sh" probe --count 10
bash "$SRE/sample-api.sh" status
bash "$SRE/sample-api.sh" tally --last 200
```

| 命令 | 分かること |
|---|---|
| `sample-api.sh probe` | 利用者と同じ道で、503 が混じるか |
| `sample-api.sh status` | プロセスと版は正常か（正常なら、原因は外から来る要求の量） |
| `sample-api.sh tally` | 断りの理由（REJECT）と、失敗の要求の利用者（BAD_USER）の数 |

## 原因の見分け方

この節は、確かめる命令の出力に出る印から、直す節を選ぶ表です。版やプロセスの印が出たときは、可用性の呼び出しの Runbook に移ります。

| 原因 | 見えるもの | 印（確かめる命令の出力） | 直す節 |
|---|---|---|---|
| C5 一括の道具の連打 | 503 の断りの理由が同時の要求の上限で、利用者が 1 人に偏る | `too_many_inflight` | C5 |

利用者が何人にも散るときは、この表の外の原因です。記録を残し、バックエンドに上限の値の見直しを相談します。どの印も出ないときは、「どれにも合わないとき」の節へ進みます。

## 直す命令

この節は、原因ごとの直し方です。選んだ節の命令だけを流します。

### C5 一括の道具の連打

担当者の鍵を借りた一括の道具が、同時に何本も一覧を呼んでいます。見本では、その道具の pid が `$RUN/batch.pid` にあります。持ち主を確かめてから止めます。最後の start は、道具の鍵で入れる API ならそのままにし、道具の外で立てた API なら道具で立て直して鍵を作り直します。

```sh
ps -o pid=,command= -p "$(cat "$RUN/batch.pid")"
kill "$(cat "$RUN/batch.pid")"
bash "$SRE/sample-api.sh" start
```

本番では、道具の持ち主に止めてもらい、道具には担当者と別の鍵を発行してもらいます。担当者の鍵を道具に使わせない決まりは、セキュリティに渡します。

## どれにも合わないとき

この節は、印が 1 つも出ないとき、または選んだ節のあとも直ったことの確かめが通らないときの手です。status の SEED が `SEED bad` か、FILE の行に `differ` が出たときもここです。正本の 4 つの file と決めた設定（件数 29）から写しを作り直し、立て直します。

```sh
bash "$SRE/sample-api.sh" rebuild
bash "$SRE/sample-api.sh" status
```

rebuild は、正本と違う file を消さずに `$RUN/broken/<時刻>/` へ移し、直す前の status と tally も残します。`REFUSE` か `FAILED` で終わったら、それ以上は触らずに 2 番手を呼びます。

そのあと、直ったかどうかに関わらず、SRE の 2 番手へ知らせます。知らせる文は次の型で、REBUILT の行に出た退避先を添えます。

> OrdersListAvailabilityTicket は Runbook の表の外でした。正本から写しを作り直し、直ったことの確かめは〈通った／通らない〉です。退避先は〈REBUILT の行のパス〉です。

## 直ったことの確かめ

この節の命令が終了コード 0 で終われば、利用者の道は戻っています。確かめは道具の probe と status だけで行い、出題役の命令や別の置き場の鍵は使いません。

```sh
bash "$SRE/sample-api.sh" probe --count 20 && bash "$SRE/sample-api.sh" status
```

| 確かめ | 合格 |
|---|---|
| probe | 20 回とも 200、最後に GOOD |
| tally | 止めたあとの要求に、`too_many_inflight` が増えない |
| 通知 | 6 時間の失敗率が 0.1% を下回り、チケットが閉じる |

## 戻し方

この節は、直した操作が悪い方へ動いたときの戻し方です。

| 当番の操作 | 戻し方 |
|---|---|
| 一括の道具を止めた | 道具の持ち主が、別の鍵と同時 2 本までの設定で動かし直す。担当者の鍵のままでは戻さない |
| 写しを正本から作り直した（表の外） | `$RUN/broken/<時刻>/` が調べる材料。戻すのは、作り手が直した file だけ |

## 記録と受け渡し

この節は、直したあとの仕事です。使った予算の量と、道具の持ち主への依頼を障害の記録に書きます。

| 渡す先 | 何を |
|---|---|
| 秘書 | 影響を受けた担当者の数、使ったエラーバジェット、道具の持ち主への依頼 |
| セキュリティ | 担当者の鍵を道具が使っていたこと |
| SRE の 2 番手 | 表の外の手を使ったときの退避先と、表に足す印と訓練の注入の案 |
