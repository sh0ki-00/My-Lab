# sre の試験ケース

> **3 行でわかる要約**
> 1. run.sh が回す試験ケースは 5 件です。どれも機械で合否が決まり、1 件でも落ちたら提出しません。
> 2. 完成例は通り、雛形と負例は名指しの決まりで落ちます。計算は原典の表と一致し、Runbook は写しの障害を手順どおりに直し、道具だけで確かめます。
> 3. スキルを直したら `bash skills/sre/evals/run.sh` を回してください。

## ケースの一覧

この節は、5 件の試験の中身です。4 件目と 5 件目は手元の見本の写しを立てて障害を起こすので、合わせて 2 分ほどかかります。

| # | ケース | 与えるもの | 合格の条件 |
|---|---|---|---|
| 1 | 完成例と雛形 | SLO 定義書の完成例と雛形 | 完成例は slo-doc-check と burn-rate を通り、雛形は穴埋めと承認者の欠けで落ちる |
| 2 | 定義書の欠けと食い違い | `fixtures/bad-slo.md` | 承認者・測り点・エラーバジェットの扱い・Runbook の 4 つで落ち、burn-rate は食い違いで落ちる |
| 3 | 原典との照合 | `workbook-reference.tsv` と、値を 1 つ変えた写し | 原典の 8 行と計算が一致する。変えた写しは不一致で落ちる |
| 4 | 当番役の訓練 | 完成例の Runbook 4 本 | 7 つの原因（シードと壊れた版は 2 通りずつ）の 9 件、Runbook ごとの表の外の 4 件、別の起動の 4 件の計 17 件が、Runbook のコードだけで直る |
| 5 | 確かめの道具 | 完成例の Runbook を 1 か所ずつ変えた写し 2 本 | 確かめで出題役の命令と別の置き場の鍵を使う写しは `[確かめの道具]` で落ちる。C4 の直す節から start を抜いた写しは、別の起動の 1 件で `[復旧]` に落ちる |

## 当番役の訓練の中身

この節は、4 件目の 1 件ごとの流れです。訓練は使い捨ての写しと 127.0.0.1 の空いたポートだけで行い、samples/ の正本と本番には何も起こしません。

| 段 | 合格の条件 |
|---|---|
| 正常の確かめ | 注入の前に probe（利用者と同じ道で一覧を呼ぶ確かめ）が GOOD |
| 注入 | 原因の C 番号の障害を起こし、probe が BAD になる |
| 見分け | 確かめる命令の出力に、印の表の文字列が出る |
| 直す | 直す命令の C 番号の節を流す |
| 確かめ | 直ったことの確かめが終了コード 0 で、probe が GOOD |
| 表の外 | 印を見ずに「どれにも合わないとき」の節を流して直り、その節に 2 番手へ知らせる手がある |
| 別の起動 | 出題役が道具の外の命令で立て、鍵を道具の読まない file に出しても、表の最後の原因の節と道具の probe で直る |
| 確かめの道具 | 直ったことの確かめが道具の命令だけで、probe を含む。外れた Runbook は訓練しない |
