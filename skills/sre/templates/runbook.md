> 2. 原因は〈数〉つに分けて見分けます。〈原因の名前を並べる〉。
> 3. 印で原因の節を選んで直します。どの印にも合わなければ、正本から写しを作り直して 2 番手へ知らせてください。

| 項目 | 内容 |

| 通知 | `〈通知の名前〉`（〈呼び出し／チケット〉） |

## 準備

この節は、命令が使う変数を決めます。どの命令の前にも、次の行を流してください。

```sh
: "${API_DIR:=〈写しの置き場〉}" "${RUN:=〈鍵とログの置き場〉}" "${PORT:=〈ポート〉}" "${SRC:=〈正本〉}" "${SRE:=skills/sre/scripts}" "${KEYS:=$RUN/keys.txt}"
export API_DIR RUN PORT SRC SRE KEYS
```

鍵の置き場は `$KEYS` の 1 つです。道具の外で立てた API に当たっても、渡された起動の命令では立て直しません。直す節の最後の `sample-api.sh start` が、道具で立て直して鍵を作り直します。

### C1 〈原因の名前〉

〈何が起きていて、何を戻すか〉。最後は `sample-api.sh start` で終えます。

```sh
〈直す命令〉

```

## どれにも合わないとき

この節は、印が 1 つも出ないとき、または選んだ節のあとも直ったことの確かめが通らないときの手です。正本と決めた設定から写しを作り直して立て直し、そのあと 2 番手へ知らせます。この節は省けません。

```sh
bash "$SRE/sample-api.sh" rebuild
bash "$SRE/sample-api.sh" status
```

〈rebuild の退避先と、REFUSE か FAILED で終わったときは触らずに 2 番手を呼ぶこと〉。

> 〈通知の名前〉は Runbook の表の外でした。正本から写しを作り直し、直ったことの確かめは〈通った／通らない〉です。退避先は〈REBUILT の行のパス〉です。

## 直ったことの確かめ

この節の命令が終了コード 0 で終われば、利用者の道は戻っています。確かめは道具の命令だけで行い、出題役の命令や別の置き場の鍵は使いません。

```sh
bash "$SRE/sample-api.sh" probe --count 20 && bash "$SRE/sample-api.sh" status
```
