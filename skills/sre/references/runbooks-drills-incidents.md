# Runbook・訓練・障害の記録

> **3 行でわかる要約**
> 1. Runbook の書き方と訓練の決まりをまとめた資料です。障害の記録と月次の信頼性レビューの書き方も載せました。
> 2. Runbook は 7 つの節と印の表で書きます。写しで起こした障害を手順どおりに直せるかは、書いた本人ではなく runbook-drill が確かめます。
> 3. Runbook と障害の記録を書くときにこの資料を開き、雛形は templates/ から写してください。

## 用語

この節は、資料に出る略語をまとめます。2 回目からは説明を省きます。

| 用語 | 意味 |
|---|---|
| Runbook | 当番の手順書。通知 1 つに 1 本 |
| 印 | 確かめる命令の出力にそのまま出る文字列。原因を 1 つに決める |
| 写し | 正本（samples/api）を tmp/flow/stage5/ か使い捨ての場所に写した見本 |
| 外形の確かめ（probe） | 利用者と同じ道で一覧を呼ぶ確かめ |
| SLO | 利用者に約束する信頼性の目標 |
| 出題役 | 訓練で障害を起こし、症状を当番役に渡す役 |
| 別の起動 | 出題役が道具の外の命令で API を立て、鍵を道具の読まない file に出した形 |

## Runbook の 7 つの節

この節は、Runbook に必ず置く節です。slo-doc-check は、定義書から結ばれた Runbook にこの 7 つの節が無いと落とします。

| 節 | 書くこと | 守ること |
|---|---|---|
| 症状 | 利用者の画面と応答に見えること | 原因の名前を書かない |
| 確かめる命令 | 読むだけの命令 | 何も変えない。出力を記録に貼れる形 |
| 原因の見分け方 | 原因・見えるもの・印・直す節の表 | 印はバッククォートで囲んだ文字列 |
| 直す命令 | 原因ごとの「### C 番号」の節とコード | 選んだ節だけを流せば直る |
| どれにも合わないとき | 正本と決めた設定から写しを作り直す命令と、2 番手へ知らせる文の型 | 省けない。どの印にも合わない障害でも、ここまで来れば止血に着く |
| 直ったことの確かめ | 外形の確かめのコード | 合格なら終了コード 0。Runbook の道具の命令（見本では sample-api.sh の probe と status）だけ |
| 戻し方 | 当番の操作を戻す方法 | 障害の前の壊れた状態には戻さない |

命令は「準備」の節の変数だけを使います（API_DIR、RUN、PORT、SRC、SRE、KEYS）。作業場の直下で流せる形にします。pid の記録（`$RUN/api.pid`）と鍵の file は、当番が手で立てた API では欠けることがあります。そこで命令は `cat "$RUN/api.pid"` ではなく `sample-api.sh pid` を使い、鍵は道具に探させます。本番の命令は人が出し、AI は流しません。

鍵の置き場は `$KEYS` の 1 つです。道具は `$KEYS` と `$RUN/keys.*` のほかは読みません。道具の鍵で入れない API に当たると、`sample-api.sh start` が道具で立て直し、鍵を `$KEYS` に作り直します（REKEY の行）。そのため直す節は、API を立て直さない節（C4、C5）でも最後を `sample-api.sh start` で終えます。道具の鍵で入れる API なら、start は何もしません。

## 見本で起こせる原因

この節は、samples/api の写しで実際に起こせる原因の一覧です。runbook-drill は、この C 番号で注入を選びます。

| C 番号 | 原因 | 注入（使い捨ての写しだけ） | 症状 |
|---|---|---|---|
| C1 | ポートの取り合い | 別のプロセスに PORT を取らせて立て直す | 404 か 000 |
| C2 | シードの壊れ | 権限を 000 にする版と、注文の shipDue の先頭に空白を足す版 | 起動しない。または一部の一覧と詳細が 500 |
| C3 | 壊れた版 | 表 customers を消す版、鍵の表を空にする版 | 500、401 |
| C4 | 止まったプロセス | SIGSTOP（端末の Ctrl-Z と同じ） | 000 |
| C5 | 一括の道具の連打 | 同じ鍵で同時に 12 本 | 一部が 503 |
| C6 | 起動の設定の誤り | 件数 50000 で立て直す | 全部が 50 ms 超え |
| C7 | 読む件数が決めた量より多い | 件数 35000 で立て直す | 遅い要求が混じる |
| 表の外 | どの Runbook の表にも無い形 | シードの中身を壊し、pid の記録なし・鍵は keys.out で手で立てる | Runbook ごとに 1 件、どれにも合わないときの節で直す |
| 別の起動 | 表の最後の原因を、出題役の起動の命令の上で起こす | 道具の外で server.py を立て、鍵は `drill-<PORT>.out`（道具は読まない）。pid の記録と `$KEYS` は無い | Runbook ごとに 1 件、その原因の節で直し、道具の probe で確かめる |

C2 の印は `SEED bad` です。status は seed を権限だけでなく、正本と中身で照らします。違う値は `SEED bad reason=content` に場所と値で出ます。2026-11-08 の当番役の訓練では、権限は正しいまま、値の先頭に空白が 1 つ付いていました。権限だけの印では見分けられませんでした。その学びをこの印に戻しました。

## 訓練の決まり

この節は、障害を起こす訓練の決まりです。障害は自分たちで先に起こして確かめますが、起こす場所は写しと 127.0.0.1 だけです。

| 決まり | 中身 |
|---|---|
| 場所 | 使い捨ての写しと、空いたポート。samples/ の正本と本番には起こさない |
| 当番役 | 書いた本人ではなく runbook-drill。Runbook のコードだけを流す |
| 確かめの命令 | 直ったかは、Runbook の道具の命令（`sample-api.sh probe`）だけで確かめる。出題役は自分の確かめの命令を渡さない。渡されても当番役は使わない |
| 出題役の起動 | 出題役が別の起動の命令で立てても、当番役はその命令で立て直さない。直す節の最後の `sample-api.sh start` が道具で立て直し、鍵を作り直す |
| 合格 | 症状が出る、印が出る、直す節で直る、確かめが終了コード 0、probe が GOOD。表の外の 1 件は、どれにも合わないときの節で直り、2 番手へ知らせる手がある。別の起動の 1 件も、同じ直す節と道具の probe で通る |
| 頻度 | Runbook を直したときと、月 1 回 |
| 記録 | MEASURE の秒を定義書の訓練の表に写す。測っていない秒は書かない |

runbook-drill は、直ったことの確かめの節に道具の外の命令があると、訓練の前に `[確かめの道具]` で落とします。probe が無いときも同じです。2026-11-08 の 2 回目の当番役の訓練では、出題役の確かめの命令が、道具と別の置き場の鍵を読んでいました。当番役は Runbook どおりに直したあと、その命令を通すためだけに、渡された起動の命令で立て直しました。その学びを、この決まりと別の起動の 1 件に戻しました。

```mermaid
flowchart LR
    A["写しを立てる"] --> B["障害を起こす"]
    B --> C["確かめる命令"]
    C --> D["印で原因を選ぶ"]
    D --> E["直す命令"]
    E --> F["直ったことの確かめ"]
```

図の読み方: 左から右へ、訓練の 1 件が進みます。どこかで止まれば、その Runbook は当番に渡せません。

## 障害の記録

この節は、障害の記録の書き方です。目的は人を責めることではなく、同じ失敗を仕組みで止めることです。

| 節 | 書くこと |
|---|---|
| 影響 | 時間、失敗した要求の数、使ったエラーバジェットの割合と計算 |
| 時系列 | 時刻と出来事。人の名前ではなく役割 |
| 検知と止血 | 利用者より先に気づけたか、Runbook どおりか、戻せたか |
| 原因 | なぜ届いたかを仕組みで。人の名前で終えない |
| 処置 | 担当・期限・完了条件。完了条件は機械で確かめられる形 |
| 学び | Runbook・通知・訓練のどこに足すか |

## 当番の上限と月次の信頼性レビュー

この節は、当番の負担の決め方と、月に 1 回見直す物です。原典は、12 時間の当番で事象を 2 件までにすることを勧めています。

| 見る物 | 超えたら |
|---|---|
| 当番 1 回の呼び出しの数 | 通知を減らすか、仕組みを直す処置を起票する |
| Runbook の無い通知 | 通知を止めるか、Runbook と訓練を足す |
| 予算の使い方 | 使い切りそうなら、リリースの決まりを取りまとめ役に伝える |
| 処置の期限切れ | 担当と期限を引き直し、月次レビューに載せる |
