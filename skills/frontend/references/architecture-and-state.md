# 構成と状態: 動く場所、置き場、取得、エラー

> **3 行でわかる要約**
> 1. 画面を部品に分け、部品ごとに動く場所（サーバー・ブラウザ・両方）を決め、状態の置き場を 1 か所にする決まりである。
> 2. 取得は要求ごとに打ち切りと失敗時の振る舞いを先に決め、行ごとの要求を作らない。打ち切りは性能予算から引かず、API の打ち切りから決める。
> 3. 5 状態（初期・読み込み中・空・エラー・成功）を全画面に置き、エラーは 2 文で出す。

## 動く場所は部品ごとに決める

取得と描画はサーバーに寄せ、入力・開閉・選択のように対話が要る部品だけをブラウザで動かす。ブラウザで動く部品が増えるほど、転送する JS が増え、初期表示が遅くなる。表の本体をサーバーで描けば、描画に使うコードは初期表示の JS に入らない。

| 部品の型 | 動く場所 | 理由 |
|---|---|---|
| ページ、一覧の表、空とエラーの表示 | サーバー | 取得と描画だけで、対話を持たない |
| 絞り込みの帯、ページ送り、詳細の面、一括操作の帯 | ブラウザ | 入力、開閉、選択を持つ |
| 文言の表、書式化の関数、トークン | 両方 | 描画の場所を問わず同じ値を使う |
| API の呼び出しと応答の検証 | サーバー | 鍵と内部の URL をブラウザに出さない。server-only を import する |

フレームワークが「サーバーの部品」を持たないときも、分け方は同じである。取得と描画を 1 つの層に、対話を別の層に置き、対話の層から取得を呼ばない。

## 状態の置き場は 1 か所

状態は出どころで分け、置き場を 1 つずつ決める。同じ値を 2 か所に持たないので、「URL は未出荷なのに表は全件」のような食い違いが起きない。派生した値（選んだ行の番号、件数の文）は描画中に計算し、状態には入れない。

| 出どころ | 置き場 | 例 |
|---|---|---|
| URL | クエリ文字列 | 保存ビュー、絞り込み、検索語、並び順、送りの起点。共有と「戻る」が効く |
| サーバー由来 | 取得の仕組みのキャッシュか、サーバーの部品の引数 | 一覧と件数、開いている詳細。古いとみなす時間を決める |
| 画面の操作 | その部品の中 | 面の開閉、選んだ行、焦点の行 |
| フォーム | 入力欄の部品の中 | 入力中の検索語。確定で URL へ |
| 利用者の設定 | サーバーに保存し、起動時に 1 回読む | 1 文字キーのオン・オフ、密度 |

副作用で派生の状態を作らない。「絞り込みが変わったら件数を再計算して state に入れる」は、2 か所目を作っている。件数は描画中に数える。

## データ取得は打ち切りと失敗時を先に決める

要求ごとに、呼ぶ時機と手段、打ち切りの時間、失敗時の表示を表にする。一覧と件数は 1 回の要求で取り、N+1（一覧の行ごとに要求を出してしまうこと）を作らない。件数が別の要求になっている API には、同じ応答に入れるよう要望を出す。

| 要求 | いつ | 打ち切り | 失敗時 |
|---|---|---|---|
| 一覧と件数 | 初期表示と、URL が変わるたび | API 自身の打ち切りに、往復の余裕 2 秒を足す。契約に無ければ 10 秒 | エラーの状態へ。自動では送り直さない。描き直しの間は古い表を薄く残す |
| 1 件の詳細 | 面を開いたとき | 一覧と同じ決め方 | 面の中に 2 文と再試行 |
| 更新（出荷指示など） | 操作のとき。冪等キーを付ける | 一覧と同じ決め方 | 打ち切りは失敗と決めず、結果を取り直して見せる。失敗は成功した件数と失敗した件数を 2 文で出し、選び直して再試行できる形にする |

打ち切りと速さの目標（性能予算）は、別の数字として決める。予算は、75 パーセンタイル（利用者の 4 人に 3 人）で収まるべき速さの目標である。バックエンドには、予算から描画の時間を引いた値（LCP 2.5 秒なら 2.0 秒）を、API の応答の目標として求める。目標を超えた応答は遅いだけで、壊れてはいない。画面はエラーにせず待ち続け、超えた分は CI（変更ごとに自動で検査する仕組み）と計測画面で見つけて直す。

打ち切りは、応答が来ないと分かる時点に置く。API の契約にある API 自身の打ち切りに、往復の余裕を足した値にする。API 自身の打ち切りは、過ぎると API が「上流の遅れ」のエラーを返す時間である。契約に無ければ 10 秒を仮置きにし、未確定に書く。10 秒は、同期の応答で待たせる長さの上限の目安である（Google AIP-151）。混む時間に画面が自動で送り直すと、遅い API に要求が重なる。送り直しは、利用者が押したときだけにする。

待つ間の見せ方は、経過した時間で段を分ける。150ms までは何も変えず、150ms で骨組みを出し、予算の時間を過ぎたら「時間がかかっています」と知らせる。打ち切りの時間が来たら、エラーの状態へ移す。知らせは role=status（焦点を移さずに読む領域）で 1 回だけ読む。

処理すると行が減る一覧（未出荷だけを出す一覧など）は、最後の行を起点に送る。ページ番号で送ると、前のページの行が減った分だけ次のページが詰まり、行を飛ばす。

## エラーは 2 文と追跡番号

エラーは「何が起きたか」と「どうすればよいか」の 2 文で出し、問い合わせで記録を引ける追跡番号を添える。コードは画面仕様とバックエンドの契約の表と 1 対 1 で結び、画面側で文を組み立てない。文言は国際化の表（ja.json など）から取る。

| 置き場 | いつ | 例 |
|---|---|---|
| 表の位置 | 一覧が取れない | 注文一覧を読み込めませんでした。しばらく待ってから、もう一度読み込んでください |
| 面の中 | 1 件の詳細が取れない | この注文を読み込めませんでした。一覧に戻って、もう一度開いてください |
| 帯の上 | 一括操作が一部失敗 | 12 件のうち 2 件を出荷指示にできませんでした。残った 2 件を選び直して、もう一度出荷指示してください |
| 画面上部 | 通信なし | インターネットに接続できません。接続を確かめてから、もう一度読み込んでください |

存在を教えてはいけないもの（他人の注文、権限の無い注文）は、どれも「見つかりません」の 1 種類で扱う。

## 5 状態を全画面に置く

どの画面にも、初期・読み込み中・空・エラー・成功の 5 状態がある。空とエラーを行き止まりにせず、条件を変える操作を残す。読み込み中の骨組み表示は 150ms 待ってから出し、出したら 300ms は消さない。明滅させない。

| 状態 | 出すもの | 次に押せる操作 |
|---|---|---|
| 初期 | 既定の条件と表の骨組み | 条件を変える |
| 読み込み中 | 150ms 後に骨組み。予算の時間を過ぎたら知らせ、打ち切りでエラーへ | 待つか、条件を変える |
| 空 | 「条件に合う注文はありません」と、条件を 1 つ外す候補 | 候補を押す |
| エラー | 2 文と追跡番号、「もう一度読み込む」 | もう一度読み込む |
| 成功 | 件数と表。選択中なら一括操作の帯 | 開く、選ぶ、操作する |

5 状態の表示は結合テスト 1 本で 5 件とも確かめる。axe（アクセシビリティの自動検査の道具）は、5 状態 × 撮る幅（計画書に図のある幅）の格子で回す。
