# アクセシビリティとテスト: 型、自動と手動、1 対 1 の対応

> **3 行でわかる要約**
> 1. 部品の作りは APG（W3C が公開する部品ごとのキーボード操作の作法集）の型から選び、要素は役割と名前で取る。
> 2. axe（アクセシビリティの自動検査の道具）が見つけるのは問題の半分ほどである。手動の 5 項目を自己点検票に書く。
> 3. 受け入れ条件とテストを 1 対 1 で結び、レベルとサイズを決め、不安定の 5 要因を固定する。

## 部品の型は APG から選ぶ

自分で振る舞いを発明しない。表、面、入力補完のそれぞれに、W3C が公開した型がある。表は「編集や選択を持つなら grid、読むだけなら table」で選ぶ。

| 部品 | 型 | キーボード | 選ぶとき |
|---|---|---|---|
| 読むだけの表 | table | Tab で表の中のリンクに止まる | 行を選ばず、並び替えは見出しのリンク |
| 選ぶ・移る表 | grid | Tab の止まり先は表で 1 つ。中は矢印（J と K を足してよい） | 行の選択、一括操作、その場の編集がある |
| 一覧を隠さない面 | 非モーダルの面（aside と見出し） | 開いたら見出しへ焦点。Esc で閉じ、焦点を行に戻す | 詳細を見ながら一覧を操る |
| 一覧を止める面 | dialog | 焦点を中に閉じ込める。Esc で閉じる | 確認、取り消せない操作 |
| 入力補完とパレット | combobox | ↑↓ で候補、Enter で確定、Esc で閉じる | 検索、コマンドパレット |

1 文字キー（J、K、S など）は、部品に焦点があるときだけ有効にし、設定でオフにできるようにする。WCAG 2.2 の 2.1.4 の求めである。

## 自動検査が見つけるのは半分

axe は、違反 0 でも「使える」の証明にならない。Deque の調査では、自動で見つかる問題は全体の 57% 前後である。残りは手動で確かめ、結果を自己点検票の数字と文で書く。

| 手動の項目 | 確かめ方 | 書き方の例 |
|---|---|---|
| キーボードだけの通し操作 | マウスを外し、主要な用事を最後まで行う | Tab 14 回、Enter 3 回で完了 |
| 焦点の見え方 | 全要素を Tab で通し、枠が見えるか。固定の帯の下に隠れないか | 隠れる要素 0 |
| 読み上げ | VoiceOver か NVDA で、表の 1 行と面の見出しを聞く | 「注文 1042、山田、12,800 円、未出荷」と読まれた |
| 200% の拡大 | ブラウザで 200% にし、横スクロールが出ないか | 横スクロールなし。列を 4 つに減らす |
| 押せる領域 | 最小の部品を DevTools で測る | 最小 44px（この会社の決まり。WCAG 2.2 の AA の下限は 24px） |

自動検査は 5 状態 × 撮る幅の格子で回す。成功の状態だけで回すと、空とエラーの表示の違反を見逃す。

## 要素は役割と名前で取る

テストは getByRole（役割と名前で要素を取る）を先に使う。役割で取れない要素は、テストの都合ではなく画面の欠陥として直す。getByTestId は使わない。

| 取り方 | 使う順 | 例 |
|---|---|---|
| getByRole | 1 | button の「出荷指示」、columnheader の「注文番号」 |
| getByLabelText | 2 | 入力欄「注文番号・氏名で絞る」 |
| getByText | 3 | 2 文のエラー、件数の文 |
| getByTestId | 使わない | 役割で取れないなら画面を直す |

## 受け入れ条件とテストは 1 対 1

受け入れ条件 1 件にテスト 1 本を結び、番号・条件・テスト名・レベル・サイズの表にする。対応の無い条件は「確かめていない」であり、テストの無い実装は「動くはず」である。

| レベル | サイズ | 何を確かめるか | 道具 |
|---|---|---|---|
| 単体 | small | 関数と部品 1 つ。URL と API の写し、書式化、部品のキー操作 | vitest と Testing Library |
| 結合 | medium | 画面 1 つ。5 状態、axe の格子。API は MSW（API を模擬する道具）で固定 | vitest か Playwright |
| 端から端まで | large | 利用者の用事 1 つ。担当者が絞り込み、選び、出荷指示する | Playwright。trace を保存 |

不安定なテストは直す対象で、再実行で誤魔化さない。要因は 5 つに決まっている。

| 要因 | 固定の方法 |
|---|---|
| 時刻 | 見本データの日時を固定し、相対時刻を表示しない |
| 乱数 | 種を固定する |
| 外部サービス | MSW で固定の応答を返す。端から端までだけ localhost の API |
| 並行 | スリープで待たず、要素の表示を待つ assertion を使う |
| 実行順序 | テストごとに見本データを作り直し、状態を共有しない |

## 視覚回帰は監修を通した枠だけを基準にする

視覚回帰（見た目の変化を画像の比較で見つけるテスト）は、基準画像との比較である。Playwright（ブラウザの自動操作の道具）の toHaveScreenshot で撮る。基準は CI と同じコンテナの Chromium で作る。手元の OS で作った画像は、書体の描画が違って差分になる。

| 項目 | 値 |
|---|---|
| 枚数 | 5 状態 × 撮る幅。撮るのは、計画書に配置の図がある幅だけ（注文一覧では 1,280・640・320 の 15 枚） |
| 撮らない幅 | 図の無い幅と、図のある幅と同じ配置になる幅。性能の測定の幅（412 など）は、性能予算の測定条件として別に持つ |
| 許容差 | maxDiffPixels 10 |
| 基準の更新 | デザイナーの監修を通した枠だけ。差分を見ずに更新しない |
