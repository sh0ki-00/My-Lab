# 証拠と安全の決まり

完了報告は、実行した証拠が揃っていて初めて出せる。AI は、取り消せない行為と外に出る行為に、承認なしで触れない。
この 2 つは、約束ではなく機械で守る。hooks（コマンドの直前と編集の直後に走る検査）と検証の命令が止める。検証の命令は、My-Lab では `tools/verify-all.sh`、他のプロジェクトでは `tmp/tools/project-verify.sh` である。

## 1. 証拠

| 決まり | 具体的には |
|---|---|
| 書く前に実行する | 「作成した」「確認した」「動く」と書く前に、確認のコマンドを実行し、結果の抜粋を残す |
| 条件ごとに対にする | 受け入れ条件 1 件につき、確認コマンドと結果の 1 行 |
| 未確認は理由つきで | 確かめられなかった条件は「未確認（理由: 検証環境がない）」と書く。黙って「充足」にしない |
| 実在を確かめる | 報告に書いたファイルのパスは、実在するものだけ |
| 検証の記録を付ける | 検証の結果は記録に残り、報告はそれを指す。My-Lab では `docs/verify/<日付>.md`、他のプロジェクトでは `tmp/.verify/last-fast.txt` か `tmp/.verify/last-full.txt` |

## 2. 安全（AI がしてよいことの線）

| 行為 | 扱い | 守る仕組み |
|---|---|---|
| `git commit`、`git push`、Issue と PR の作成 | そのたびに社長の承認（Claude Code は確認ダイアログ。確認が効かない Cursor では、社長が自分の端末で実行する） | hooks の判定本体 `hooks/guard-core.sh` |
| `reset --hard`、`clean -f`、`stash drop`、ブランチの削除、履歴の書き換え | 承認 | 同上 |
| コンフリクトの機械的な解消（`--ours`、`--theirs`） | 承認。片側を捨てる解消は原則しない | 同上 |
| 本番環境への適用、データの削除、外部への送信、秘密の取り扱い | 社長が行う。AI は手順と差分を示して止まる | 役割スキルの禁止の節 |
| 常時ルール（`~/.claude/CLAUDE.md`、User Rules）の書き換え | しない。本文を社長に渡す | `install.sh` は書き込まない |
| 合図の語 `APPROVE_GIT=1` | 使わない。AI が付けることは最も重い違反 | 判定本体がどの設定でも拒否する |

## 3. 秘密

- 鍵、パスワード、トークンをファイルやログやチャットに書かない。設定は環境変数か秘密管理の仕組みで渡す。
- `verify-all.sh` の秘密の検出（`gitleaks`）が 1 件でも見つけたら、出さずに直す。
- 社長の実案件の写しは `tmp/` の下に置き、git に入れない。

## 4. 自動の検証

実装するときは、ローカルでできる検証を人の判断を待たずに回す。表の「検証」は、冒頭に書いた置き場ごとの命令を指す。

| 場面 | 何が走るか |
|---|---|
| ファイルを直した直後 | そのファイルの検査（日本語・資料・図・シェル） |
| 作業を終える前 | 検証の `--fast`。FAIL のあいだは終われない |
| commit の承認を求める前 | 検証の `--full` |

道具が無いことによる SKIP は、FAIL と同じに扱う。道具は段階 0 で一度だけ入れた（`shellcheck`、`gitleaks`、`trivy`、`semgrep`、Playwright、Lighthouse、axe）。
